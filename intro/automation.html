자동화 설계와 결과

테스트가 통과한다는 말과 테스트가 쓸모 있다는 말은 다릅니다. 아무것도 확인하지 않는 테스트도 통과하기 때문입니다. 그래서 자동화를 짤 때 두 가지를 함께 설계했습니다 — 화면이 바뀌어도 살아남는 구조, 그리고 고장을 심었을 때 실제로 깨지는지 확인하는 절차입니다.

자동화 157건자동화 대상 케이스 152건심은 고장 4종빌드 PC웹_Ver1.0_Dev_RC25

테스트가 붙잡을 접점을 먼저 심었다

검증 대상을 다 만든 뒤에 테스트를 붙이면, 테스트가 화면 생김새와 문구에 매달리게 됩니다. 버튼 글자 하나만 바뀌어도 무더기로 깨지고, 화면에 안 나타나는 것(저장소에 남은 데이터 같은)은 아예 확인할 수 없습니다. 그래서 만들기 시작할 때부터 네 갈래를 심어 두었습니다.

접점규칙왜 필요한가
요소 셀렉터테스트는 요소를 data-testid로만 찾습니다. CSS 클래스·화면 문구로 찾는 것은 금지문구·디자인이 바뀌어도 테스트가 살아남아야 합니다
상태 조회·제어 API전역 객체로 내부 상태의 읽기 전용 사본을 노출하고, 초기화(reset)를 반드시 제공합니다격리 계열 검증(슬롯 오염·삭제 기억 재등장·계정 잔존)은 화면에 나타나지 않아 이 통로가 유일한 검증 수단입니다
실행 조건 파라미터mock 응답은 시드 파라미터로 결정적으로 고정하고, 결함 주입 스위치를 파라미터로 둡니다시드는 실패 재현을, 주입은 테스트 탐지력 증명(§6)을 가능하게 합니다
데이터 주입목록·집계·표시가 읽는 조건 데이터는 전역 객체의 주입 API로 넣습니다. 사람용 편집 UI를 함께 두는 경우 두 경로는 같은 저장소를 씁니다화면 조작만으로 경계 조건(최대 개수·중복·빈 상태)을 만들면 세팅 비용이 테스트마다 커지고 조건 재현이 셀렉터 경로에 묶입니다. 저장소가 갈리면 사람 검증과 자동화의 재현이 어긋납니다

테스트 이름이 곧 케이스 번호

리포트에서 빨간 줄 하나를 보고 시트의 어느 케이스인지 바로 찾을 수 있어야 합니다. 그래서 테스트 함수 이름에 케이스 번호를 그대로 넣었습니다. 이름을 짓는 규칙 하나로 실행 결과와 설계 문서가 이어집니다.

환경 때문에 깨지지 않게

자동화가 가끔 실패하기 시작하면, 사람은 곧 결과를 믿지 않게 됩니다. 「또 그거겠지」가 되는 순간 자동화는 있으나 마나 합니다. 그래서 가짜 실패를 만드는 원인을 규칙으로 막았습니다.

몇 초 기다리기 금지

브라우저가 느려지면 「2초 기다린다」는 환경에 따라 깨집니다. 시간이 아니라 상태 표식이 바뀌는 것을 기다립니다.

테스트마다 초기화

앞 테스트가 남긴 데이터가 뒤 테스트의 결과를 바꾸면, 실패의 원인이 코드인지 순서인지 알 수 없습니다. 매번 초기화하고 시작합니다.

응답을 고정할 수 있게

AI 응답이 매번 다르면 실패를 재현할 수 없습니다. 시드를 주면 같은 응답이 나오도록 만들어, 실패한 조건을 그대로 다시 만들 수 있습니다.

고장을 심어 탐지력을 증명한다

커버리지는 「빠짐없이 봤다」까지만 말합니다. 봤을 때 알아채는지는 다른 문제입니다. 그래서 고장을 하나씩 켜고 전체를 다시 돌려, 담당 케이스만 실패하는지를 봅니다. 담당은 실행 결과가 아니라 고장을 심은 지점을 지나며 그 오동작을 판정하는가로 정합니다 — 지나가기만 하는 케이스는 담당이 아닙니다.

이 자동화가 확인하지 않는 것

할 수 있는 것보다 할 수 없는 것을 밝히는 쪽이 신뢰를 만듭니다. 적어도 세 가지는 이 검증의 범위 밖입니다.

실제 AI 모델의 품질

응답은 규칙으로 만든 대체 구현입니다. 그래서 여기서 잰 반영률·어투 점수는 모델의 성능이 아니라 시스템이 규칙대로 조립하는지를 말합니다.

실제 결제와 외부 인증

결제와 본인인증은 흉내만 냅니다. 실패 경로와 되돌림은 검증하지만, 결제사·인증사와의 실제 연동은 대상이 아닙니다.

사람이 봐야 하는 것

어투와 관계 단계가 어울리는지는 채점표로 사람이 봅니다. 자동화가 대신할 수 있는 척하지 않고, 사람 몫으로 남겨 두었습니다.

검증 범위와 한계의 정본은 프로젝트의 청사진 문서이고, 실행 결과의 정본은 검증 리포트입니다.

이 문서는 파생물입니다 — gen_intro_html.py --page auto로 재생성합니다. 접점 규칙은 rules/sut-automation.md에서, 담당 근거는 결함 기대표에서, 실행 결과는 커밋된 매트릭스 표에서, CI 단계는 워크플로 파일에서 읽습니다.
