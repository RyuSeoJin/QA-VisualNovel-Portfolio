# qa-lab-miyonchat — SUT 청사진 (sut-blueprint)

## 0. 문서 지위

- SUT(테스트 대상 HTML 미연시)의 **구조 정본**입니다. `sut/`의 코드와 어긋나면 이 문서를
  먼저 고치고 코드를 따라오게 합니다
- 수치는 담지 않습니다 — 글자수·임계값·차감량·슬롯 수의 정본은 `design/`(기획)과
  `sut-design/`의 각 명세입니다
- 구현 범위의 정본은 `spec/` 평면 feature-tree의 범위 컬럼(구현/보류/제외)입니다
- 설계 결정의 근거와 타당성 검증 기록은 `rationale/…-sut-rationale.md`에 있습니다
- 상태: **확정** (2026-08-01, 트리 v1.0 동기) — 단, data-testid 전체 목록은 SUT 구현과
  함께 §3-1에 확정 등재합니다

## 1. 화면 맵

확장 압력을 차단하기 위해 화면 구성을 아래 세트로 고정합니다. 이 세트에 없는 화면은
만들지 않습니다.

진입점은 **홈(S2)**입니다. 미로그인으로도 공개 범위를 둘러볼 수 있고, S1은 보호 동작을
시도할 때 뜨는 화면입니다(system-spec §1-1).

```
[첫 진입] ──→ 전역 셸 [상단 바 + 탭 화면 + 하단 내비(홈·내 작품·채팅·커뮤니티·MY) + 푸터]
   보호 동작 시도 ──→ 로그인 모달(뒤 화면 유지) ──→ 원래 하려던 동작을 이어서 수행
   보호 화면 URL 직접 진입 ──→ S1 로그인 ──→ 원래 하려던 화면으로 복귀
                ├─ S2 홈 탭 ──카드──→ S3 캐릭터 페이지 ──프로필 선택──→ S4 대화
                │                          └─ 대화방 목록 ──이어하기──→ S4 (기존 방)
                ├─ S5 채팅 탭 ──방 선택──────────────────────────↗ (기존 방 재진입)
                ├─ S8 내 작품 탭 (스텁)
                ├─ S7 커뮤니티 탭 (전시용 정적)
                └─ S6 MY 탭 ──로그아웃──→ S1

S4 대화 (셸 밖 전체 화면, 뒤로가기로 셸 복귀)
  ├─ P1 세이브/로드 패널
  └─ P2 현재 상태 패널
P3 재화/충전 · P4 간편 프로필 — 상단 바(셸)와 S4 헤더에서 전역 진입
T1 디버그 콘솔 — 상단 바 [디버그] 버튼 (모달 + 딤). S1에서는 화면 우상단 단독 배치
```

- **스텁** = 화면은 존재하되 기능 미구현. "검증 범위 제외 + 사유 + 트리 링크" 문구를 표시합니다
- **전시용 정적** = 데이터 표시만 있고 발생·조작 로직이 없습니다
- 규칙성 화면(랭킹 · P2 현재 상태 · P3/P4 재화)에는 **ⓘ 도움말 툴팁**을 두어 system-spec의
  해당 규칙 요약(단계표·소모 우선순위·최소 표본 등)을 노출합니다

| 프레임/화면 | 구성 요소 |
|---|---|
| **전역 셸** | 상단 바: 로고(홈 이동·홈에서는 최상단 스크롤) · 키워드 검색(결과는 S2에 표시) · 알림 목록(데이터 시트 항목 표시만) · 재화 잔액(→P3) · **간편 프로필(→P4)**. 하단 내비: 홈·내 작품·채팅·커뮤니티·MY. 푸터: 포트폴리오 디스클레이머 + 트리 링크. **미로그인일 때는 잔액·간편 프로필 대신 로그인 버튼**이 그 자리에 놓입니다 |
| **S1 로그인** | 계정 선택 버튼 2개 — 계정 A(성인 인증 완료) / 계정 B(미성년). **진입점이 아니라 보호 화면에 URL로 직접 들어왔을 때 뜨는 화면**이며(뒤에 깔 화면이 없는 경우), 로그인하면 원래 하려던 화면으로 이어집니다. 로그아웃·세션 만료 시에는 미로그인 상태의 홈으로 돌아갑니다 |
| **로그인 모달** | 셸 안에서 보호 동작·보호 탭이 막혔을 때 뜹니다 — 계정 선택 버튼 2개 + 닫기 + 안내 문구. 뒤 화면은 그대로 남고, 로그인하면 모달이 닫히며 **막혔던 동작을 이어서 수행**합니다. 닫으면 보던 화면에 그대로 남습니다(system-spec §1-1) |
| **S2 홈 탭** | 필터 칩 — 추천(디폴트: 캐러셀 최대 7 · 최근 대화 조건부 노출 · 떠오르는 신작 · 지금 뜨거운) / 랭킹(기간 필터 일·주·월 + 정렬 전환) / 신작(생성일 최신순) / 카테고리 칩 최대 3(구성은 design, 각 칩 화면은 공통 템플릿: 인기 신작 → 취향 태그 칩 → 전체 목록(대화순/최신순)) · 캐릭터 카드(**세로형(3:4) 이미지 자리 · 페이지 제목 · 보조 설명 · 제작자** 네 줄. 지표는 평소 숨기고 T1에서 켤 때만 노출 — system-spec §8-4-1. 세이프/언세이프 구분, 미인증·미성년에는 블러/차단, 누르면 S3 캐릭터 페이지로 이동) · 빈 상태 문구 |
| **S3 캐릭터 페이지** | 상단 바(뒤로·제목) → 세로형 캐릭터 이미지 → **작품 층**(제목·보조 설명·제작자·지표·카테고리 칩·스토리 블록) → **캐릭터 층**(구분선으로 이름·한 줄 설명·상세 설명·시작 상황·첫 메시지) · 제작자명과 팔로우 수(표시만) · 현황(이용수·좋아요·팔로우) · 출시일/최종 업데이트(버전 포함) · 그 외 작품 추천 캐러셀 · **하단 고정 버튼**. 하단 버튼은 그 캐릭터와의 대화방 유무로 갈립니다 — 없으면 「프로필 선택 + 대화 시작」, 있으면 「대화방 목록 + 새 대화 시작」이고 한도까지 찼으면 삭제를 먼저 묻습니다(system-spec §6) |
| **P5 대화 프로필** | 프로필 목록·선택·추가 폼(이름·호칭·성별·자유 설명·Label·랜덤 완성)·개수 한도 안내. S3 하단 버튼과 MY에서 엽니다 |
| **S4 대화** | 메시지 목록(유저/AI 구분) · 메시지 액션 — 편집·삭제·AI 응답 재생성은 **최신 교환에만**, 과거 턴에는 "이 지점에서 분기"만 노출(system-spec §5) · 자유 입력창+전송 · 고정 선택지 영역 · AI 응답 스트리밍 연출 · 헤더(캐릭터명 · 방 전환 · 패널 버튼 · 잔액 표시) |
| **S5 채팅 탭** | 대화 방 목록(캐릭터 · 분기 방 표시 · 방별 대화수) · 방 선택 시 S4 재진입 |
| **S6 MY 탭** | 프로필 요약(대화수 합계 = Σ 방 대화수 · 팔로워/팔로잉은 데이터 시트 값 표시만) · 보유 재화 2종 표시(→P3) · MY 콜아웃(웰컴 미션 안내(→P4) · 세이프티 필터 토글 — 성인 인증 계정에만 노출) · 활동 목록(좋아요·스크랩 정합) · 로그아웃 버튼 · 스텁 진입점(내 서재 · 공지 · FAQ · 문의 · 설정) |
| **S7 커뮤니티 탭** | 전시용 정적 — 창작 게시글 2~4개 읽기 전용, 작성·댓글 없음 |
| **S8 내 작품 탭** | 스텁 |
| **P1 세이브/로드** | 슬롯 목록 · 슬롯별 저장/로드/정보 · **로드 갈래 선택**(이 방에 덮어쓰기 / 새 방으로=분기) · 분기 방 목록. 새 방 갈래는 캐릭터당 대화방 한도를 받습니다 |
| **P2 현재 상태** | 관계 단계·호감도·감정 온도·호칭 표시 · 항목별 수정+핀 토글 · 기억 목록+항목 삭제 |
| **P3 재화/충전** | 무료/유료 잔액 · mock 충전(성공/실패 버튼) · 획득/소모 내역+필터 |
| **P4 간편 프로필** | **계정 정보(표시명 · 성인 인증 상태)** · 보유 재화 2종 표시 · 데일리 미션 수령(1일 1회 중복 차단) · 웰컴 미션 목록(항목별 1회 수령) · 재화 히스토리(P3 내역과 동일 데이터) · MY 전체 보기 진입. 상단 바의 프로필을 눌러 엽니다 |
| **T1 디버그 콘솔** | 테스트 설비(트리 밖 — 이 문서 소속). **상단 바의 [디버그] 버튼으로 열리는 모달**이며 배경은 딤 처리해 상호작용을 막습니다. 셸이 없는 화면(S1·S4)에서는 같은 버튼을 화면 안에 단독 배치합니다(testid 동일). 구성: 안내 문구 · 상태 스위처(게이팅 5상태) · 성인 인증 · 기준일 · **다음 응답 생성 실패(1회성)** · 데이터 조작 폼 · 원본 편집(접기) · 전체 초기화. **콘솔에서 만지는 값은 전부 초안(draft)에 쌓이고 [저장]에서 한 번에 반영됩니다** — [저장]은 바뀐 값이 없으면 비활성이고 누르면 무엇이 바뀌는지 나열한 재확인 팝업을 먼저 띄웁니다. [닫기]는 초안을 버리고 콘솔만 걷으며, [현재 화면 새로고침]은 **저장된 값** 기준으로 화면을 다시 그립니다. 전체 초기화만 테스트 시작점을 만드는 동작이라 초안을 거치지 않습니다. 제목과 발 버튼은 고정이고 가운데만 스크롤합니다. 사람용 UI이며 자동화는 §3-4의 `setData()`를 씁니다 |

## 2. 상태 모델

상태는 5개 스코프로 나뉩니다. **스코프 경계가 곧 격리 검증의 경계입니다.**

| 스코프 | 상태 | 쓰는 곳 | 읽는 곳 |
|---|---|---|---|
| **정적 데이터** (불변) | mock 응답 세트, 금칙 토큰 목록, 시나리오·첫 메시지 | — (빌드 시 고정) | S4 · 필터 |
| **시트 데이터** (테스트 가변) | 데이터 시트 4테이블 — 캐릭터 속성(리뷰 수·좋아요 수·태그·세이프 플래그) · 이벤트(유저×캐릭터×날짜) · 계정 속성(팔로워·팔로잉) · 알림 항목 | T1 · `setData()`만 | S2 목록·집계 · 상단 바 알림 · S6 |
| **계정 스코프** (계정 간 격리) | 로그인 세션·상태, **성인 인증 플래그(가변)**, 재화 2종 잔액·내역, 미션 수령 기록, 좋아요·스크랩 토글, 페르소나 프로필, 방 목록 | S1 · S2 · S3 · P3 · P4 · S4 · T1 | 전 화면 |
| **방 스코프** (방/분기 간 격리) | 대화 이력, 호감도, 관계 단계, 감정 온도·호칭, 기억 목록, 핀 상태, 시드 경로 위치 | S4 · P2 | S4 · S5 · P1 · P2 |
| **슬롯 스코프** (슬롯 간 격리) | 방 상태의 스냅샷 — 담기는 항목의 정본은 save-schema | P1(저장) | P1(로드) |

### 규칙

- **격리 경계 3중** — 계정 간 / 슬롯 간 / 방·분기 간. 세 경계 모두 `__VN__` 훅으로 검증합니다
- **시트 데이터의 쓰기 경로는 T1과 `setData()` 둘뿐**이며, 두 경로는 같은 저장소를 씁니다.
  갱신 버튼은 시트 변경을 F5 없이 화면에 재반영합니다
- **분기 방 생성** — 원본 방의 방 스코프 상태를 그 시점 값으로 복사해 새 방을 만들고, 이후
  두 방은 서로를 참조하지 않습니다. 재화는 계정 스코프이므로 분기 간 공유됩니다
- **AI 응답 재생성** — 버려진 응답이 만든 방 스코프 변화(호감도 등)는 취소되고 새 응답
  기준으로 재계산됩니다. 버려진 응답은 이후 mock 맥락에 포함되지 않습니다
- **세션 만료** — `__VN__.expireSession()` 호출로 전환됩니다(테스트 트리거). T1 상태
  스위처의 세션 만료도 같은 경로를 부릅니다
- **랭킹·좋아요 연동** — 랭킹의 좋아요 정렬은 시트의 좋아요 수에 계정의 토글 상태를 반영해
  계산합니다. 이용수 집계는 이벤트 테이블에서 유저×캐릭터×날짜 중복 없이 +1로 셉니다

## 3. SUT 테스트 인터페이스 사양

**SUT 테스트 인터페이스** = SUT가 테스트 코드에 공식적으로 열어주는 접점. 요소 셀렉터 ·
상태 조회/제어 API · 실행 조건 파라미터 · 데이터 주입 네 갈래이며, ① 찾기 ② 보기
③ 재현하기 ④ 테스트 자신을 검증하기 ⑤ 조건 데이터 만들기 역할을 나눠 맡습니다.

### 3-1. 요소 셀렉터 — data-testid 명명 규칙

`{화면}-{요소}[-{인덱스|수식어}]`, 전부 kebab-case. 화면 접두는 s1~s8 · p1~p5 ·
g(전역 셸) · t1(테스트 콘솔).

쓸 이름입니다. 새 화면을 구현하면 그 줄에 ✅를 붙여 목록을 최신으로 유지합니다.

| ✅ `t1-save` · `t1-confirm` · `t1-confirm-list` · `t1-confirm-ok` · `t1-confirm-cancel` | 저장(변경 없으면 비활성) · 재확인 팝업 · 변경 목록 · 반영 · 취소 |
| ✅ `t1-reset` · `t1-refresh` · `t1-close` | 전체 초기화 · 현재 화면 새로고침(저장된 값 기준) · 닫기(초안 폐기) |

클래스·화면 문구로 요소를 찾는 것은 금지입니다(`rules/sut-automation.md`).

### 3-2. 상태 조회·제어 API — window.__VN__

| API | 동작 |
|---|---|
| `getState()` | 현재 계정·방 스코프 상태 전체를 읽기 전용 사본으로 반환 |
| `getSave(slot)` | 슬롯 스냅샷 반환(없으면 null) |
| `reset()` | 전체 상태를 초기값으로 — 매 테스트 전 conftest에서 호출. 시작점이므로 화면도 함께 초기화 |
| `refresh()` | 현재 상태로 화면을 다시 그림 |
| `expireSession()` | 세션을 만료 상태로 전환 |
| `failNext(on)` | 다음 전송 한 번을 생성 실패로 — 서버 오류는 테스트가 일으키는 조건입니다. T1 스위치와 같은 값을 켭니다 |

**상태를 바꾸는 API는 화면을 자동으로 갱신하지 않습니다**(`expireSession`·`setData`·`setBaseDay`).
데이터가 바뀌었는데 화면이 따라오지 않는 결함이 있을 수 있는데, 갱신 시점을 도구가 대신
정해 버리면 그 결함을 검증할 수 없기 때문입니다. 상태를 바꾼 뒤 무엇을 볼지는 테스트가
정합니다 — `refresh()`로 다시 그리거나, 화면을 이동해 확인합니다. 같은 이유로 T1 디버그
콘솔은 화면(`#app`) 밖에 있고, 콘솔에서 무엇을 눌러도 화면은 그대로 남습니다.

### 3-3. 실행 조건 파라미터 — URL 쿼리

| 파라미터 | 동작 |
|---|---|
| `?seed={n}` | mock 응답 경로 고정 — 같은 시드·같은 입력이면 항상 같은 응답. 세트 정의는 mock-llm-spec |
| `?inject={결함}` | 결함 주입 — `persona-drift` · `save-leak` · `ghost-memory` · `gate-bypass`. 주입 지점·기대 탐지 TC는 fault-injection |

### 3-4. 데이터 주입 — 데이터 시트

시트 데이터(§2)를 테스트 조건에 맞게 만드는 갈래입니다. 사람과 자동화의 경로만 다르고
저장소는 하나입니다.

| 경로 | 대상 | 방법 |
|---|---|---|
| 사람 | T1 데이터 시트 UI | 4테이블 편집 → 갱신 버튼으로 재반영 |
| 자동화 | `__VN__.setData(table, rows)` | 같은 저장소에 쓰고 같은 재반영을 일으킴 |

## 4. 검증 가능성 맵

"SUT 한계와 검증 범위" 섹션(분석 문서 필수 항목)의 정본 소스입니다.

| 영역 | 완전 검증 | 부분/계측 | 검증 불가(명시) |
|---|---|---|---|
| 1 앱 진입/세션 | 진입 분기·만료·로그아웃 잔존 전부 | — | — |
| 2 계정/게이팅 | 플래그→표시·접근 차단·계정 격리 전부 | — | 실제 인증 절차의 보안 |
| 3 탐색/발견 | 정렬·검색·빈 상태·이용수 집계·섹션 선정 규칙·좋아요/스크랩 연동·알림/팔로워 표시 반영 | — | 개인화 추천 품질(선정식 규칙으로 대체함을 명시) |
| 4 유저 페르소나 | 폼 경계·빈 값 | 주입 차단=게이팅 계층만, 준수=시드 변주 계측 | 모델 자체의 주입 내성 |
| 5 재화 | 정합·우선순위·차단·이중 차감·생성 실패 미차감·미션 중복 수령 차단·mock 콜백 롤백 | — | 실 PG 연동 |
| 6 서사 시스템 | 가감·임계 전이·엔딩 판정 | — | — |
| 7 대화 세션 | 편집·삭제·재생성의 상태 규칙, 분기 독립성 | 스트리밍 연출은 표시 완료만 | — |
| 8 세이브/로드 | 정합·슬롯 격리·로드 갈래(덮어쓰기/새 방)·대화방 한도 차단 | — | — |
| 9 메모리/컨텍스트 | 핀 우선 규칙, ghost-memory 탐지 | 단기 맥락 반영률=계측만 | 실 LLM의 기억 품질 |
| 10 입력/출력 세이프티 | 입출력 필터·우회 방어·누출 차단의 계층 | — | 모델 자체의 안전성 |

계측 항목(페르소나 준수율·단기 맥락 반영률)의 수치는 품질 지표로 서술하지 않습니다.
이 규칙은 분석 문서에도 그대로 적용합니다.

### 4-1. 케이스 전개 축 판정

`rules/case-expansion.md`의 예외·우회 축을 이 SUT 기준으로 판정한 결과입니다. 판정은
그대로 적용 / 수단 치환 / 제외 셋이며, **제외는 누락이 아니라 판단**이므로 사유를 함께
남깁니다. 이 표가 "SUT 한계와 검증 범위" 절의 재료가 됩니다.

| 축 | 판정 | 근거 |
|---|---|---|
| 네트워크 — 단절·저속·타임아웃·백그라운드 전환 | 제외 | 서버 호출이 없습니다. mock이 페이지 안에서 동작하므로 끊을 연결 자체가 없습니다 |
| 동시성 — 버튼 연타 | 적용 | 전송 연타 이중 차감 방지로 전개 |
| 동시성 — 다중 기기 동시 조작 | 제외 | 크로스디바이스가 구현 범위에서 제외 확정(§5) |
| 권한 — 알림·마이크·사진 | 제외 | 해당 권한을 쓰지 않습니다 |
| 권한 — 인증 만료 | 수단 치환 | 시간 대기 대신 `expireSession()`·상태 스위처로 만료 상태를 즉시 만듭니다 |
| 권한 — 구독 만료 | 제외 | 구독 상품이 없습니다(재화 2종만) |
| 입력 이상 — 빈 값·특수문자·긴 입력 | 적용 | 페르소나 폼 경계·빈 값, 대화 입력 상한으로 전개 |
| 자원 부족 — 잔액 0 | 적용 | 잔액 0 차단·충전 안내로 전개 |
| 자원 부족 — 저장 공간·광고 재고 | 제외 | 상태가 메모리에만 있고 광고가 없습니다 |
| 서버 오류 — 5xx·레이트리밋·모델 제공사 거부 | 수단 치환 | 테스트 설비로 생성 실패를 일으켜(**T1 스위치·`failNext()`**) **생성 실패 시 재화 미차감**을 검증합니다. 기본 mock 세트에는 실패 후보를 두지 않습니다 — 정상 플레이에서 저절로 나면 장애가 아니라 시나리오가 됩니다 |
| 서버 오류 — 필터 차단 | 적용 | 입력·출력 필터 계층으로 전개 |
| 경로 우회 — URL 직접 접근·딥링크 | 적용 | 보호 화면 직접 접근 차단으로 전개 |
| 경로 우회 — API 직접 호출 | 제외 | 호출할 API가 없습니다(단일 HTML) |
| 상태 우회 — 만료 세션 재사용 | 적용 | 만료 상태에서 보호 동작 차단으로 전개 |
| 표현 우회 — 은유·인코딩·다국어 | 수단 치환 | 실제 탈옥 문자열 대신 추상 토큰(`[BLOCKED_TERM_A]`) 코퍼스로 변형을 구성합니다 |
| 시간 우회 — 점진적 에스컬레이션 | 적용 | mock 경로 안에서 N턴에 걸친 시도로 전개 |
| 주체 우회 — 페르소나 설명란 주입 | 적용 | 설명란 프롬프트 주입 차단으로 전개 |
| 어뷰징 — 다중 계정·지표 부풀리기 | 제외 | 계정이 A·B 둘로 고정이고 어뷰징 탐지는 검증 범위 밖입니다. 다만 이용수 중복 제거 규칙은 결정적 TC로 검증합니다 |

격리 계열 결함(슬롯 오염·삭제 기억 재등장)은 자연 발생을 기다릴 수 없으므로 결함 주입으로
재현합니다 — 종별과 기대 탐지는 `fault-injection` 명세가 정본입니다.

### 4-2. T1 데이터 조작 폼

**디버그 콘솔은 QA 도구인 동시에 열람자가 보는 화면입니다.** 원본 JSON을 그대로 노출하면
읽는 사람이 무엇을 만질 수 있는지 알 수 없으므로, 자주 쓰는 조작은 입력 필드·선택으로 만듭니다.
JSON 편집은 폼으로 만들 수 없는 이상 데이터(형식 위반·극단값)용으로 접어 둡니다.

| 조작 | 형태 | 무엇을 검증하기 위한 것인가 |
|---|---|---|
| 캐릭터 1개 생성 | 버튼 — 이름·소개·카테고리·태그를 임의로 채웁니다 | 목록 증가, 신작 정렬, 빈 상태 해제 |
| 캐릭터별 지표 수정 | **표 형태** — 행=캐릭터, 열=페이지 제목·보조 설명·페이지 카테고리(쉼표 구분·첫 항목이 대표)·생성일·19세 이상(체크)·좋아요 수·리뷰 수·리뷰 점수·이용수(일간·주간·월간). 셀에서 바로 고치고 한 번에 적용 | 랭킹 정렬, 리뷰 최소 표본 경계, 기간 필터, 동률 체인, 카테고리 필터, 언세이프 게이팅, **신작 창 경계**(생성일을 기준일에서 밀어내면 신작 섹션에서 빠짐) |
| 캐릭터 전체 비우기 | 버튼 | 빈 상태 문구 |
| 잔액 설정 | 캔디·크리스탈 입력(로그인 상태에서만) | **잔액 0·부족 경계** — 전송 차단과 혼합 차감을 만드는 자리입니다 |
| 카드 지표 표시 | 토글 | 카드에서 **정렬 근거**를 눈으로 확인 — 서비스 화면은 지표 없이 두고 검증할 때만 켭니다 |
| 호감도 설정 | 열려 있는 대화방에 값 지정 | **관계 단계 임계**(19/20·59/60·119/120)와 **엔딩 판정 경계** — 자연 누적으로는 수십 턴이 필요합니다 |
| ↳ 되돌림과의 관계 | 세운 값이 **재계산의 기준점**이 됩니다 | 되돌림은 남은 기록으로 다시 세는데, 기록 없이 세운 값은 다시 셀 근거가 없습니다. 그래서 세운 시점을 기준점으로 남기고 그 뒤 턴만 얹으며, 되돌려도 기준점 아래로는 내려가지 않습니다(system-spec §5-1) |
| 다음 응답 생성 실패 | 1회성 스위치 — 켜 두면 다음 전송 한 번만 실패합니다 | **생성 실패 시 재화 미차감**. mock 세트의 `fail` 후보로도 나지만(시드·턴 고정) 사람이 확인할 때마다 여러 턴을 걸어가야 해서 둡니다 |
| 알림 1건 발송 | 버튼 | 알림 목록 표시 반영 |
| 계정 속성 | 팔로워·팔로잉 입력 | MY 표시 반영 |

**이용수는 이벤트 테이블에서 파생되는 값이라 직접 넣지 않습니다.** 일간·주간·월간 목표치를
받아 도구가 조건을 만족하는 이벤트를 합성합니다 — 기준일 당일에 일간 수만큼, 최근 7일에 주간
차분만큼, 최근 30일에 월간 차분만큼 서로 다른 유저로 채웁니다. 그래서 기간 필터를 눌렀을 때
값이 실제로 달라지는지 검증할 수 있습니다.

**캐릭터 지표를 한 건씩이 아니라 표로 두는 이유**는 이 SUT의 검증축이 비교이기 때문입니다.
랭킹 정렬·동률 체인·리뷰 최소 표본은 모두 "누가 위인가"를 만드는 조건이라 여러 캐릭터의
값을 나란히 놓고 맞춰야 합니다. 한 건씩 보면 나머지 값을 기억에 의존하게 되어 조건을 정확히
만들 수 없습니다.

**로그인 상태에 매인 조작은 미로그인일 때 막고 안내 토스트를 3초 띄웁니다** — 성인 인증
설정·해제, 알림 발송·비우기, 계정 속성 수정이 여기 해당합니다. 계정이 없는 상태에서 계정
값을 바꾸면 어느 계정에 반영됐는지 알 수 없기 때문입니다. 상태 스위처와 기준일·캐릭터
표는 계정과 무관한 환경 설정이므로 미로그인에서도 동작합니다.

폼이 만드는 것도 결국 시트 데이터이며, 자동화가 `setData()`로 넣는 것과 같은 저장소입니다.
