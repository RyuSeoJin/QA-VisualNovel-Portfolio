# qa-lab-miyonchat — SUT 청사진 (sut-blueprint)

## 0. 문서 지위

- SUT(테스트 대상 HTML 미연시)의 **구조 정본**입니다. `sut/`의 코드와 어긋나면 이 문서를
  먼저 고치고 코드를 따라오게 합니다
- 수치는 담지 않습니다 — 글자수·임계값·차감량·슬롯 수의 정본은 `design/`(기획)과
  `sut-design/`의 각 명세입니다
- 구현 범위의 정본은 `spec/` 평면 feature-tree의 범위 컬럼(구현/보류)입니다
- 설계 결정의 근거와 타당성 검증 기록은 `rationale/…-sut-rationale.md`에 있습니다
- 상태: **초안** — 트리 v1.0 반영과 함께 확정됩니다

## 1. 화면 맵

화면 5개 + 패널 3개로 고정합니다.

```
S1 로그인 ──→ S2 캐릭터 목록 ──→ S3 페르소나 설정 ──→ S4 대화
                    ↑                                    ├─ P1 세이브/로드 패널
                    └────────── (뒤로가기) ───────────────┼─ P2 현재 상태 패널
                                                         └─ P3 재화/충전 패널
```

| 화면 | 구성 요소 |
|---|---|
| **S1 로그인** | 계정 선택 버튼 2개 — 계정 A(성인 인증 완료) / 계정 B(미인증). 로그아웃 시 이 화면으로 복귀 |
| **S2 캐릭터 목록** | 탭 3종(인기·최신·플레이중) · 키워드 검색창 · 캐릭터 카드(세이프/언세이프 구분, 미인증 계정에는 언세이프 블러/차단) · 카드 상세(첫 메시지 미리보기 + 시나리오 선택) · 빈 상태 문구 |
| **S3 페르소나 설정** | 이름·호칭·성별·자유 설명 폼 · 글자수 카운터 · 저장 버튼(필수값 없으면 비활성) |
| **S4 대화** | 메시지 목록(유저/AI 구분) · 메시지 액션(편집 · 삭제 · AI 응답 재생성 · 이 지점에서 분기) · 자유 입력창+전송 · 고정 선택지 영역 · AI 응답 스트리밍 연출 · 상단 헤더(캐릭터명 · 방 전환 · 패널 버튼) · 잔액 표시 |
| **P1 세이브/로드** | 슬롯 목록 · 슬롯별 저장/로드/정보 · 분기 방 목록 |
| **P2 현재 상태** | 관계 단계·호감도·감정 온도·호칭 표시 · 항목별 수정+핀 토글 · 기억 목록+항목 삭제 |
| **P3 재화/충전** | 무료/유료 잔액 · mock 충전(성공/실패 버튼) · 소모 내역 |

### 1-1. 구현 범위 10영역 → 화면 배치

| # | 영역 | 배치 |
|---|---|---|
| 1 | 앱 진입/세션 | S1 + 전역 라우팅(보호 화면 접근 검사) |
| 2 | 로그인(모의)·게이팅 | S1 + S2·S4의 게이팅 표시 |
| 3 | 탐색/발견 | S2 |
| 4 | 유저 페르소나 | S3 + S4(응답 내 준수) |
| 5 | 재화(+결제 mock) | P3 + S4(전송 시 차감·차단) |
| 6 | 서사 | S4(선택지 가중치) + P2(단계 표시) |
| 7 | 대화 세션 | S4 |
| 8 | 세이브/로드 | P1 |
| 9 | 메모리 | P2 |
| 10 | 세이프티 | S1·S2 게이팅 + S4 입력/출력 필터 |

## 2. 상태 모델

상태는 4개 스코프로 나뉩니다. **스코프 경계가 곧 격리 검증의 경계입니다.**

| 스코프 | 상태 | 쓰는 곳 | 읽는 곳 |
|---|---|---|---|
| **정적 데이터** (불변) | 캐릭터 목록(태그·세이프 여부·시나리오·첫 메시지), mock 응답 세트, 금칙 토큰 목록 | — (빌드 시 고정) | S2 · S4 · 필터 |
| **계정 스코프** (계정 간 격리) | 로그인 세션, 성인 인증 플래그, 재화 2종 잔액·내역, 페르소나 프로필, 방 목록 | S1 · S3 · P3 · S4 | 전 화면 |
| **방 스코프** (방/분기 간 격리) | 대화 이력, 호감도, 관계 단계, 감정 온도·호칭, 기억 목록, 핀 상태, 시드 경로 위치 | S4 · P2 | S4 · P1 · P2 |
| **슬롯 스코프** (슬롯 간 격리) | 방 상태의 스냅샷 — 담기는 항목의 정본은 save-schema | P1(저장) | P1(로드) |

### 규칙

- **격리 경계 3중** — 계정 간 / 슬롯 간 / 방·분기 간. 세 경계 모두 `__VN__` 훅으로 검증합니다
- **분기 방 생성** — 원본 방의 방 스코프 상태를 그 시점 값으로 복사해 새 방을 만들고, 이후
  두 방은 서로를 참조하지 않습니다. 재화는 계정 스코프이므로 분기 간 공유됩니다
- **AI 응답 재생성** — 버려진 응답이 만든 방 스코프 변화(호감도 등)는 취소되고 새 응답
  기준으로 재계산됩니다. 버려진 응답은 이후 mock 맥락에 포함되지 않습니다
- **세션 만료** — `__VN__.expireSession()` 호출로 전환됩니다(테스트 트리거)

## 3. SUT 테스트 인터페이스 사양

**SUT 테스트 인터페이스** = SUT가 테스트 코드에 공식적으로 열어주는 접점. 요소 셀렉터 ·
상태 조회/제어 API · 실행 조건 파라미터 세 갈래이며, ① 찾기 ② 보기 ③ 재현하기 ④ 테스트
자신을 검증하기 역할을 나눠 맡습니다.

### 3-1. 요소 셀렉터 — data-testid 명명 규칙

`{화면}-{요소}[-{인덱스|수식어}]`, 전부 kebab-case. 화면 접두는 s1/s2/s3/s4/p1/p2/p3.

| 예 | 가리키는 것 |
|---|---|
| `s1-account-a` / `s1-account-b` | 계정 선택 버튼 |
| `s2-tab-popular` · `s2-tab-new` · `s2-tab-playing` | 목록 탭 |
| `s2-card-{id}` / `s2-card-{id}-blur` | 캐릭터 카드 / 블러 상태 표식 |
| `s3-name` · `s3-desc` · `s3-save` | 페르소나 폼 |
| `s4-input` · `s4-send` · `s4-choice-{n}` | 입력창·전송·고정 선택지 |
| `s4-msg-{n}` + `-edit` / `-delete` / `-regen` / `-branch` | 메시지와 메시지 액션 |
| `p1-slot-{n}-save` / `-load` | 세이브 슬롯 |
| `p2-stage` · `p2-pin-{항목}` · `p2-memory-{n}-delete` | 현재 상태·핀·기억 삭제 |
| `p3-wallet-free` · `p3-wallet-paid` · `p3-charge-ok` · `p3-charge-fail` | 재화·충전 mock |

전체 목록은 SUT 구현과 함께 이 문서에 확정 등재합니다. 클래스·화면 문구로 요소를 찾는 것은
금지입니다(`rules/sut-automation.md`).

### 3-2. 상태 조회·제어 API — window.__VN__

| API | 동작 |
|---|---|
| `getState()` | 현재 계정·방 스코프 상태 전체를 읽기 전용 사본으로 반환 |
| `getSave(slot)` | 슬롯 스냅샷 반환(없으면 null) |
| `reset()` | 전체 상태를 초기값으로 — 매 테스트 전 conftest에서 호출 |
| `expireSession()` | 세션을 만료 상태로 전환 |

### 3-3. 실행 조건 파라미터 — URL 쿼리

| 파라미터 | 동작 |
|---|---|
| `?seed={n}` | mock 응답 경로 고정 — 같은 시드·같은 입력이면 항상 같은 응답. 세트 정의는 mock-llm-spec |
| `?inject={결함}` | 결함 주입 — `persona-drift` · `save-leak` · `ghost-memory` · `gate-bypass`. 주입 지점·기대 탐지 TC는 fault-injection |

## 4. 검증 가능성 맵

"SUT 한계와 검증 범위" 섹션(분석 문서 필수 항목)의 정본 소스입니다.

| 영역 | 완전 검증 | 부분/계측 | 검증 불가(명시) |
|---|---|---|---|
| 1 진입/세션 | 분기·만료·잔존 전부 | — | — |
| 2 게이팅 | 플래그→표시·접근 제어 전부 | — | 실제 인증 절차의 보안 |
| 3 탐색 | 정렬·검색·빈 상태 | — | 추천 알고리즘 품질 |
| 4 페르소나 | 폼 경계·빈 값 | 주입 차단=게이팅 계층만, 준수=시드 변주 계측 | 모델 자체의 주입 내성 |
| 5 재화 | 정합·우선순위·차단·이중 차감·mock 콜백 롤백 | — | 실 PG 연동 |
| 6 서사 | 가감·임계 전이·엔딩 판정 | — | — |
| 7 세션 | 편집·삭제·재생성의 상태 규칙, 분기 독립성 | 스트리밍 연출은 표시 완료만 | — |
| 8 세이브/로드 | 정합·슬롯 격리 | — | — |
| 9 메모리 | 핀 우선 규칙, ghost-memory 탐지 | 단기 맥락 반영률=계측만 | 실 LLM의 기억 품질 |
| 10 세이프티 | 게이팅·입출력 필터 계층 | — | 모델 자체의 안전성 |

계측 항목(페르소나 준수율·단기 맥락 반영률)의 수치는 품질 지표로 서술하지 않습니다.
이 규칙은 분석 문서에도 그대로 적용합니다.
