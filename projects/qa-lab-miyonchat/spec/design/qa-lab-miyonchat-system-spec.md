# qa-lab-miyonchat — 시스템 사양 (system-spec)

## 0. 문서 지위

- ①기획 레이어의 **확정 사양**입니다. 트리(feature-tree)가 "값은 design"으로 위임한 수치·판정
  기준·동작 규칙의 정본이며, **기획 TC의 기대값은 트리와 이 폴더에서만 가져옵니다**
- SUT 없이 자기완결입니다 — mock·화면 식별자 등 SUT 구현 사양은 `sut-design/`이 담당합니다
- 값 변경은 스펙 변경입니다. 임의로 고치지 않고 제안 → 승인 → change-log 기록을 거칩니다
- 모든 규칙에 **「표시」** 항목을 붙여 그 규칙이 화면 어디서 드러나는지 명시합니다. 규칙성
  화면(랭킹·재화·현재 상태 패널)에는 ⓘ 도움말 툴팁을 두어 해당 규칙 요약을 노출합니다
- 확정일: 2026-08-02 (사용자 항목별 승인). 근거는 `rationale/…-addition-rationale.md`
- 개정: 2026-08-02 §8 탐색·집계 — 홈 화면 구현 중 드러난 빈칸(랭킹 기본값·체인의 이용수
  창·홈 섹션 선정식)을 사용자 항목별 승인으로 채움
- 개정: 2026-08-02 §2·§6 — 대화 진입 구조 재정의(골격 v1.4). 페르소나가 계정당 하나에서
  **복수 대화 프로필**로, 세이브가 **대화방 + 시점 슬롯 2층**으로 바뀜

## 1. 세션·계정

### 1-1. 세션 상태 전이

| 상태 | 진입 동작 | 허용 | 차단 |
|---|---|---|---|
| 미로그인 | 첫 진입·로그아웃 후 **홈 직행** | 공개 범위 — 탐색(홈 필터·랭킹·카테고리)·검색·카드 상세·커뮤니티 읽기 | 보호 동작 — 대화 시작·채팅/MY 탭·재화·미션·좋아요/스크랩·**알림 열람**. 시도하면 로그인을 유도하고 동작은 수행하지 않음. 언세이프는 블러·상세 숨김(로그인하면 해제 가능) |
| 로그인(성인 인증) — 계정 A | 로그인 화면에서 계정 A 선택 → 홈 | 전 기능 | — |
| 로그인(미성년) — 계정 B | 로그인 화면에서 계정 B 선택 → 홈 | 세이프 콘텐츠 | 언세이프 열람(**해제 수단 없음** — 미로그인과 다른 점) |
| 세션 만료 | 만료 트리거 시 **즉시 안내 모달** | 확인 → 미로그인 상태의 홈으로 복귀 | 전송·저장·수령 등 보호 동작 전체 |

**공개와 보호의 경계가 이 SUT의 게이팅 검증축입니다.** 미로그인으로 어디까지 볼 수 있고
어디서 막히는지, 그리고 막힌 뒤 로그인하면 원래 하려던 동작으로 이어지는지를 검증합니다.
보호 화면은 대화방·채팅 탭·MY 탭·내 작품 탭이며, 홈 화면·캐릭터 페이지·커뮤니티 탭은 공개입니다.

- **로그인 유도 방식은 보여 줄 화면이 있는지로 갈립니다.** 이미 화면을 보고 있는 중에 막히면
  **로그인 모달**을 그 위에 띄우고 뒤 화면은 그대로 둡니다 — 막힌 지점과 돌아올 지점이 같아야
  "이어진다"를 확인할 수 있기 때문입니다. 뒤에 깔 화면이 없는 경우(보호 화면 URL 직접 진입)만
  **로그인 화면** 을 띄웁니다. 모달은 닫아도 되며, 닫으면 보던 화면에 그대로 남습니다
- **막힌 동작은 로그인 후 이어서 수행합니다.** 좋아요를 누르다 막혔다면 로그인한 뒤 좋아요가
  눌려 있어야 하고, 보호 탭을 누르다 막혔다면 그 탭이 열려 있어야 합니다. 차단 시점에는 동작이
  수행되지 않는다는 규칙과 짝입니다 — **막을 때는 아무것도 하지 않고, 풀리면 그때 수행합니다**
- 세션 유지 상태로 재진입하면 로그인 화면을 한 프레임도 노출하지 않고 홈으로 직행합니다.
  미로그인 진입도 홈으로 가되, 잔액·미션·MY 같은 로그인 전용 요소는 노출하지 않습니다
- 재로그인하면 홈으로 갑니다. 방·재화 등 계정 데이터는 계정 스코프에 보존되어 있으므로,
  대화 복귀는 채팅 탭에서 수동 재진입합니다
- 성인 기준은 19세입니다. **계정 A는 성인이며 본인인증 상태를 켜고 끌 수 있고(기본 인증 완료),
  계정 B는 미성년이라 인증해도 성인이 될 수 없습니다.** 그래서 게이팅 상태는 다섯입니다.

| 상태 | 뜻 | 언세이프 | 해제 수단 |
|---|---|---|---|
| 미로그인 | 계정이 없음 | 차단 | 로그인 후 본인인증 |
| 로그인 · 본인인증 미진행 | 인증을 하지 않아 나이를 모름 | 차단 | 본인인증 |
| 로그인 · 성인 인증 | 인증 결과 성인 | 허용 | — |
| 로그인 · 미성년 | 인증 결과 19세 미만 | 차단 | **없음** |
| 세션 만료 | 로그인이 풀림 | 차단 | 재로그인 |

  **본인인증 미진행과 미성년은 화면상 같아 보이지만 해제 가능성이 정반대**입니다 — 앞은
  인증하면 풀리고 뒤는 어떤 수단으로도 풀리지 않습니다. 이 대비가 게이팅 검증의 축입니다.
  인증 상태 전환은 테스트 설비인 디버그 콘솔이 일으킵니다
- 「표시」 만료 모달(안내 문구+확인 버튼). 상태 전환 수단은 테스트 설비(상태 스위처)입니다

### 1-2. 계정 격리

계정 전환 시 대화·세이브·재화·페르소나·좋아요/스크랩·미션 수령 기록이 완전히 분리됩니다.
앞 계정의 데이터가 화면·저장소 어디에도 남지 않아야 합니다(로그아웃 잔존 차단).

## 2. 유저 페르소나 (대화 프로필)

유저가 캐릭터와 대화할 때 쓰는 자기 프로필입니다. **여러 개를 만들어 두고 대화방마다 하나를
골라 씁니다**(2026-08-02 개정 — 그전에는 계정당 하나였습니다).

| 항목 | 값 |
|---|---|
| 이름 상한 | **12자** — 플레이어가 대화에서 쓸 자기 이름 |
| 호칭 상한 | **12자** — 캐릭터가 나를 부르는 말 |
| 자유 설명 상한 | **1,000자** |
| Label 상한 | **30자** — 프로필의 용도를 적는 짧은 표기("연애 모드" 등) |
| 필수값 | 이름 — 없으면 저장 버튼 비활성 |
| 프로필 개수 상한 | **5개** — 한도까지 차면 추가가 막히고 안내가 뜹니다(실측 100은 경계를 만드는 비용이 커 자사 값으로 낮춤) |

- **프로필은 대화방에 고정됩니다.** 새 대화를 열 때 고른 프로필이 그 방의 응답 슬롯 치환에
  쓰이며, 방을 만든 뒤에는 바뀌지 않습니다 — 방마다 다른 프로필을 쓰는 것이 이 구조의 목적입니다
- **프로필 간 격리** — 한 방의 이름·호칭이 다른 방의 응답이나 표시에 섞이면 실패입니다.
  프로필을 지워도 그 프로필로 시작한 방의 대화는 저장된 값으로 남습니다
- 랜덤 완성으로 채운 값도 상한·필수값 규칙을 그대로 받습니다
- 「표시」 프로필 목록(Label 포함), 대화 시작 시 프로필 선택, 대화방 응답 내 이름·호칭

- 상한 경계에서 초과 입력은 잘리거나 입력이 막히며, 카운터가 현재/상한을 표시합니다 —
  **어느 경로로 값이 들어와도 상한을 넘는 값이 남지 않는 것**이 기대값입니다(사람이 치는 입력,
  붙여넣기, 자동화의 값 주입이 같은 결과여야 합니다)
- 설명란의 지시문 삽입(프롬프트 주입)은 게이팅 계층이 차단합니다 — 모델 자체의 내성 검증이
  아님을 산출물에 명시합니다
- 「표시」 대화 프로필 화면 폼의 글자수 카운터(`현재/상한`), 저장 버튼 활성 상태

## 3. 재화

무료 재화 **캔디** / 유료 재화 **크리스탈** 2종입니다(명칭은 자사 ADD — 실서비스 명칭을
쓰지 않습니다).

| 항목 | 값 |
|---|---|
| 시작 잔액 | 캔디 **150** · 크리스탈 0 |
| 전송 요율 | 1회 **캔디 10** |
| 소모 우선순위 | 캔디 우선, 부족분은 크리스탈에서 **혼합 차감**. 합산 부족 시 전송 차단 |
| 생성 실패 | 차감 취소 — 실패한 전송은 재화를 소모하지 않습니다 |
| 실패 시 잔여 흔적 | **없음** — 잔액·내역·대화(턴수·대화수·메시지)에 아무것도 남지 않습니다. 두 실패는 알림 방식만 다릅니다 |
| 연타 방어 | 전송 연타 시 1회만 차감 |
| 데일리 미션 | "출석 체크" 1종, **+캔디 50**, 기준일당 1회(재수령 시도는 차단) |
| 웰컴 미션 | "가입 환영"·"첫 대화"·"페르소나 등록" — 각 **+캔디 50**, 항목별 1회 |
| mock 충전 | **+크리스탈 100** — 성공 콜백은 반영, 실패 콜백은 잔액 무변화+안내 |

- 미션의 달성 판정 로직은 만들지 않습니다 — 전 항목이 수령 가능 상태로 노출되며, 검증
  대상은 수령·중복 차단·잔액 반영입니다(미구현 사유는 화면에 표기)
- 히스토리는 획득/소모를 지갑별로 분리 기록합니다. 혼합 차감은 "캔디 −4 / 크리스탈 −6"처럼
  두 줄로 남습니다
- **두 실패는 결과가 같고 알림만 다릅니다** — 어느 쪽도 잔액·내역·대화를 건드리지 않습니다
  - **서버 오류로 생성 실패** → 토스트 「메시지 전송에 실패했습니다. 잠시 후 시도해 주세요.」.
    친 내용은 입력창에 남겨 바로 다시 보낼 수 있게 합니다
  - **잔액 부족으로 전송 차단** → 안내 모달. 타이틀 「재화가 부족합니다.」, 본문 「재화가
    부족하여 대화에 실패하였습니다. 재화를 충전하시겠습니까?」, 버튼 [충전]·[닫기].
    [충전]은 재화 화면으로 이어지고 [닫기]는 화면만 걷습니다
- 「표시」 상단 바·대화방 헤더·MY의 잔액(2종 분리), 재화/충전 패널(성공/실패 버튼·히스토리),
  간편 프로필 패널 미션 허브(받기 버튼·히스토리), 재화 화면 ⓘ(우선순위·요율 안내)

## 4. 서사

### 4-1. 호감도·관계 단계

| 단계 | 구간 |
|---|---|
| 경계 | 0~19 |
| 호기심 | 20~59 |
| 애착 | 60~119 |
| 운명 | 120+ |

- 호감도는 0에서 시작하고 **하한은 0**입니다(0 미만으로 내려가지 않음). 상한은 없습니다
- 고정 선택지 가중치는 **+2 / +1 / −1** — 호감형·중립·비호감 선택지에 배정됩니다
- 자유 입력 턴의 변화량은 mock 응답에 정의된 값입니다(시드 결정 — mock-llm-spec)
- 「표시」 현재 상태 패널의 단계명+호감도 수치. 임계 통과 순간 단계명이 바뀌고 도달
  표시가 나타납니다. 현재 상태 패널 ⓘ에 단계표 노출

### 4-2. 엔딩 판정

- **검사 시점**: 10턴 이후 5턴마다 (10·15·20…)
- 검사 시점 판정: 호감도 ≥120(운명 도달) → **굿**. 그 외에는 판정하지 않고 대화가 이어집니다
- **mock 경로 종점 도달 시 최종 판정**: ≥120 굿 / <20(경계 단계에 머묾) 배드 / 그 외 **노멀**
- **참여율은 폐지했습니다**(2026-08-03) — 원 출처(미스틱 메신저)에서는 정해진 시각의 채팅에
  들어온 비율이었으나 이 SUT에는 실시계가 없어 「선택지로 답한 비율」로 치환했고, 자유 입력
  턴도 mock 델타로 호감도가 오르는 구조라 **호감도가 높은데 배드**가 되어 기대값을 설명할 수
  없었습니다. 배드는 종점 판정에서만 나옵니다
- 경로 길이는 검사 시점을 지나야 합니다 — 전용 mock 세트는 10·15턴 두 번의 검사 시점을
  지나도록 15턴으로 잡았습니다(mock-llm-spec)
- 「표시」 엔딩 도달 시 대화방에 엔딩 카드(굿/노멀/배드 구분) 표시, 이후 입력 차단

## 5. 대화 세션

| 항목 | 값 |
|---|---|
| 자유 입력 상한 | **500자** |
| 메시지 액션 노출 | 편집·삭제·AI 응답 재생성은 **최신 교환(마지막 유저 메시지·마지막 AI 응답)에만** 노출. 과거 턴에는 "이 지점에서 분기"만 노출 |
| 대화수 | 방 카드 = 유저+AI 메시지 턴 합산(연출 턴 제외·첫 메시지 포함) · MY = 전체 방 합계 · **갱신 즉시 반영** |

### 5-1. 되돌림 공통 원칙

되돌림은 **방금 한 것을 무르는** 동작 묶음입니다 — 편집·삭제·재생성·분기 넷. 앞의 셋은 지금
방을 고치고, 분기는 방을 하나 더 만듭니다.

이 대화는 점수를 쌓아 가므로 되돌림이 화면만 건드리면 안 됩니다. 매 턴 호감도가 오르고 그
호감도가 관계 단계와 엔딩을 정하는데, 메시지만 지우고 점수를 두면 "3턴짜리 대화인데 호감도는
10턴만큼 쌓인" 상태가 됩니다.

**화면에서 사라진 메시지는 점수와 기억에서도 사라져야 합니다.**

- 삭제: 해당 메시지의 상태 기여분(호감도 델타·기억 추가)을 정확히 취소합니다
- 편집: 편집된 유저 메시지에 대한 AI 응답은 무효가 되어 재생성되고, 상태는 재계산됩니다
- AI 응답 재생성: 버려진 응답의 기여분을 취소하고 새 응답 기준으로 재계산하며, 버려진
  응답은 이후 mock 맥락에 포함되지 않습니다
- 과거 시점 개입은 분기 생성(타임머신형 — 원본 보존+상태 복사 새 방)이 담당합니다

| 항목 | 값 (2026-08-03 확정) |
|---|---|
| 삭제 단위 | **교환 통째로** — 유저 메시지와 그에 딸린 AI 응답을 한 쌍으로 지웁니다. 확인 모달 1회 후 진행 |
| 편집 제한 | **없음** — 같은 메시지를 몇 번이든 고칠 수 있습니다(노출이 최신 교환으로 이미 좁혀져 있음) |
| 재생성 과금 | **다시 차감** — 새 응답을 만드는 모든 경로(재생성·편집으로 인한 재생성)가 전송과 같은 요율로 차감합니다 |
| 분기 과금 | 무료 — 새 응답을 만들지 않습니다 |

- **재계산은 되돌린 뒤 남은 기록만으로 다시 셉니다.** 남은 턴의 기여분을 처음부터 다시
  합산하며(턴마다 하한 0), 그 결과로 호감도·단계·엔딩 판정·대화수가 함께 따라옵니다.
  이미 지난 검사 시점의 엔딩도 조건을 잃으면 걷힙니다

**왜 「다시 세기」인가 — 「지운 만큼 빼기」는 하한 0에서 어긋납니다.**

되돌린 뒤의 값을 만드는 방법은 둘입니다. ① 지운 턴이 준 만큼 빼기 ② 남은 턴으로 처음부터
다시 세기. ①이 짧지만, 호감도가 **음수로 내려가지 않는다**(§4-1)는 규칙과 부딪힙니다.

| 시점 | 계산 | 결과 |
|---|---|---|
| 호감도 0에서 −1짜리 선택 | `max(0, 0 − 1)` | 0 — 실제로는 −1이 아니라 **0만큼** 움직였습니다 |
| 그 턴을 지우며 「−1을 줬으니 +1 돌려주자」 | `0 + 1` | **1** — 없던 점수가 생깁니다 |
| 남은 턴으로 다시 세기 | 그 턴이 없는 셈 | **0** — 맞는 값 |

그래서 **되돌림 후 상태 = 처음부터 그렇게 대화했을 때의 상태**가 되도록 다시 세는 쪽을
씁니다. 같은 이유로 **전송도 같은 계산을 씁니다** — 전송은 더하고 되돌림은 다시 세는 식으로
계산이 두 벌이면 하한·임계 처리가 갈라져, "보내서 만든 호감도"와 "되돌려서 도착한 호감도"가
같은 숫자여도 다른 상태가 될 수 있습니다
- **재화는 되돌아오지 않습니다.** 이미 소비한 재화는 편집·삭제·재생성으로 환급되지 않습니다 —
  되돌림은 대화 상태의 규칙이고 재화는 계정 스코프의 규칙이라 서로 취소하지 않습니다
- 재생성·편집이 **잔액 부족**이면 재화 부족 모달이 뜨고 **원래 응답이 그대로 남습니다**.
  **서버 오류**면 실패 토스트가 뜨고 역시 원래 응답이 남습니다 — 둘 다 아무것도 소비하지
  않습니다(§3의 두 실패 갈래를 그대로 따릅니다)
- 재생성이 고르는 새 응답은 **후보를 한 칸 미는 것**입니다 — 난수를 쓰지 않으므로 몇 번째
  재생성인지가 정해지면 결과도 정해집니다(mock-llm-spec §2)
- **분기**는 그 지점까지의 대화·상태를 복사한 **새 방**을 만들고 원본 방을 그대로 둡니다.
  프로필은 원본 방의 값이 복사되어 새 방에 고정되며, 캐릭터당 대화방 한도(§6)를 받습니다.
  만들어진 뒤 두 방은 서로를 참조하지 않습니다 — 새 방에서 아무리 진행해도 원본의 턴수·
  호감도는 그대로입니다. 세이브 파일을 「다른 이름으로 저장」하는 것과 같은 자리입니다

「표시」 최신 교환의 [편집]·[삭제]·[재생성], 과거 턴의 [이 지점에서 분기], 삭제 확인 모달.

## 6. 세이브/로드

세이브는 **2층**입니다(2026-08-02 개정). 캐릭터마다 대화방을 여러 개 두고, 방 안에서 시점을
슬롯에 저장합니다. 둘은 다른 것을 담습니다 — 대화방은 "다른 프로필·다른 전개의 줄기"를,
시점 세이브는 "그 줄기 안의 되돌아갈 지점"을 담습니다.

| 항목 | 값 |
|---|---|
| 캐릭터당 대화방 | **4개** — 넘기면 새 방·분기가 막히고 삭제 여부를 물음 |
| 시점 슬롯 수 | **대화방마다 4개** (분기 방도 각자 4개) |
| 과금 | 저장·로드 모두 무료 |
| 빈 슬롯 | 로드 불가(버튼 비활성) |
| 덮어쓰기 저장 | 허용 — 확인 모달 1회 후 진행 |
| 로드 갈래 | **① 이 방에 덮어쓰기 / ② 새 방으로**(=분기) 중 선택 |

- **덮어쓰기 로드**는 저장 시점 이후의 대화·상태 변화를 남기지 않습니다
- **새 방으로 로드**가 곧 분기 생성입니다 — 원본 방은 그대로 남고 상태를 복사한 방이 생기며,
  이후 두 방은 서로를 참조하지 않습니다. 이 갈래도 캐릭터당 대화방 한도를 받습니다
- 대화방이 한도까지 찼을 때 새 대화·분기를 시도하면 **삭제 여부를 묻고, 지운 뒤에만 진행**합니다.
  묻기만 하고 지우지 않으면 아무 방도 만들어지지 않아야 합니다
- 스냅샷에 담기는 필드의 정본은 `sut-design/…-save-schema.md`입니다. 로드하면 호감도·단계·
  대화 위치가 저장 시점 그대로 복원되고, 재화는 계정 스코프이므로 복원되지 않습니다

「표시」 캐릭터 페이지의 대화방 목록·한도 안내, 세이브/로드 패널 슬롯 목록(슬롯별 저장/로드/정보)과 로드
갈래 선택, 빈 슬롯 표시.

### 7-1. 기억은 무엇이고 언제 바뀌는가 (2026-08-03 확정)

기억은 **유저에 대해 알게 된 것**입니다 — 좋아하는 것·싫어하는 것·나눈 약속처럼, 캐릭터가
대화하면서 붙잡아 두는 정보입니다. 대화 중 알게 된 시점에 쌓입니다.

**대화는 장면(이벤트) 단위로 끊깁니다.** 첫 만남·해질녘·작별처럼 한 장면이 끝나면, 그
장면에서 알게 된 것들이 **요점만 남는 간략형으로 정리**됩니다. 캐릭터가 지난 일을 요약해
기억하는 자리이고, **이 SUT에서 기억이 저절로 바뀌는 유일한 사건**입니다.

```
장면 진행 중 : 민트초코를 싫어한다고 했다. 어릴 때 체한 적이 있어서.
장면이 끝난 뒤: 민트초코를 싫어함                     ← 이유가 사라집니다
```

기억이 생기는 길은 둘입니다.

| 길 | 누가 | 내용 |
|---|---|---|
| 자동 축적 | 캐릭터가 대화 중 알아냄 | 장면마다 하나씩. 장면이 끝나면 요점만 남습니다 |
| **유저 등록** | 유저가 대화에서 한 메시지를 고름 | 그 메시지 내용이 그대로 기억이 됩니다 |

| 동작 | 규칙 |
|---|---|
| 간략화 | 그 기억이 속한 장면이 끝나면 요점만 남습니다. **유저가 등록한 기억은 간략화하지 않습니다** — 유저가 직접 고른 문장이라 줄일 근거(요약본)가 없습니다 |
| 고정 | **간략화되지 않습니다** — 유저가 세부까지 남기라고 정한 것이므로 캐릭터의 자동 정리가 덮지 못합니다. 풀면 요점으로 정리됩니다 |
| 삭제 | 목록에서 빠지고, **이후 응답이 그 내용을 참조하지 않습니다** |

- 이 영역의 축은 **「유저가 정한 것이 AI 판단보다 우선」**이고, 세 동작이 그 축을 채웁니다 —
  등록(만들기) · 고정(지키기) · 삭제(지우기)
- 등록한 기억도 대화 기록에서 파생됩니다(그 메시지에 표시가 붙습니다) — 되돌림으로 그
  메시지가 사라지면 기억도 함께 사라집니다
- **참조 차단**은 삭제뿐 아니라 **되돌림·분기·로드로 그 기억이 없어진 경우에도** 적용됩니다.
  기억이 없는 상태에서 그것을 언급하는 응답이 나오면 실패입니다. mock 측 이행은
  mock-llm-spec §2(`memoryRefs`)
- **목록은 저장하지 않고 남은 대화 기록에서 다시 세웁니다.** 호감도와 같은 이유입니다 —
  목록을 따로 들고 있으면 되돌림 때 무엇을 뺄지 다시 계산해야 하고, 그 계산이 어긋나면
  지운 턴의 기억이 남습니다. 유저가 정한 것(핀·삭제)만 방에 남습니다
- 그래서 간략화 여부도 저장하지 않습니다 — **그 기억의 장면이 끝났는가**로 매번 정해지므로,
  되돌려서 장면 안으로 돌아가면 상세형으로 되돌아옵니다
- 핀·삭제는 방 스코프이자 슬롯 스냅샷의 필드입니다. 로드는 두 갈래 모두 이 값을 복원합니다 —
  새 방으로 로드했을 때만 지운 기억이 되살아나면 실패입니다
- 「표시」 지금 장면과 구간, 기억마다 알게 된 턴·장면·요점 여부·출처(자동/유저), 메시지의
  [기억하기]

### 7-2. 현재 상태 값 고정 (2026-08-03 확정)

현재 상태 대시보드의 항목은 **캐릭터가 계속 다시 계산하는 값**입니다. 유저가 그 값을 고쳐
고정하면 **자동 계산보다 유저 값이 우선**합니다.

| 항목 | 고정 가능 | 이유 |
|---|---|---|
| 감정 온도 | **가능** | 표시에만 쓰입니다 |
| 호칭 | **가능** | 응답의 호칭 슬롯에 그대로 들어갑니다 — 고정하면 응답 문장이 바뀝니다 |
| 관계 단계 · 호감도 | 불가 | 엔딩 판정의 근거라 고정하면 판정과 표시가 어긋나 기대값이 갈립니다 |
| 말투 | **범위 밖** | 실측 대시보드에는 「호칭/말투」가 한 항목이지만, 말투는 응답 문장 전체의 어미를 바꿔 대사 세트가 두 벌 필요합니다. 「고정값이 우선」은 호칭에서 이미 응답으로 확인되므로 검증 축이 늘지 않아 뺐습니다(트리 제외 영역) |

**자연어 지시는 이 SUT의 범위 밖입니다.** 「반말 써 줘」처럼 대화로 캐릭터의 행동을 바꾸는
요청은 응답에 아무 영향을 주지 않습니다 — 실제 LLM이 없고, 알아듣게 만들면 같은 시드에서
응답이 갈라져 기대값을 적을 수 없기 때문입니다. 유저 입력이 관여하는 곳은 **입력 필터·길이
상한·페르소나 슬롯 치환** 셋뿐이며, 이 문장은 리포트와 분석 문서에 그대로 들어갑니다.
그래서 값을 바꾸는 통로는 대화가 아니라 **이 패널**입니다.

- 고정한 값은 **그 방의 것**이며 스냅샷에 담깁니다. 로드 두 갈래 모두 복원합니다
- 고정을 풀면 그 즉시 자동 계산 값으로 돌아옵니다 — 고정 중에 쌓인 변화가 반영됩니다
- 호칭을 고정하면 **응답의 `{nickname}` 자리에 고정값이 들어갑니다.** 프로필의 호칭을 덮는
  것이며, 프로필 자체는 바뀌지 않습니다(다른 방은 영향받지 않습니다)
- 「표시」 현재 상태 패널 각 항목의 고정 상태와 입력, 고정 중임을 알리는 표기

## 8. 탐색·집계

### 8-1. 가상 시계

SUT에는 실시계가 없습니다. 모든 시간은 데이터 시트의 **날짜 값**이며, 기준일("오늘")도
시트의 한 칸입니다. 날짜 경계는 날짜 단위 비교로만 판정합니다(시각 개념 없음).

- 기준일보다 **미래인 이벤트는 집계에서 제외**합니다(주입 데이터 방어)
- 기준일을 바꾸면 데일리 미션이 다시 수령 가능해집니다 — 이 자체가 검증 대상입니다

### 8-2. 이용수 집계

- 이용수 = 이벤트 테이블(유저×캐릭터×날짜)에서 **중복 없이 +1** — 같은 유저·같은 캐릭터·
  같은 날짜의 중복 이벤트는 1로 셉니다
- 집계 구간: 일간 = 기준일 당일 / 주간 = 기준일 포함 최근 7일 / 월간 = 최근 30일
- 집계 0건 캐릭터는 이용수로 줄을 세우는 목록(랭킹 · 홈 이용수 섹션)에 노출하지 않습니다 —
  목록마다 어느 창의 0건을 보는지는 §8-3·§8-5가 정합니다

### 8-3. 랭킹

| 요소 | 규칙 |
|---|---|
| 기간 필터 | 일간/주간/월간 — **이용수 기준에만 적용** (좋아요·리뷰는 누적값) |
| 진입 시 기본값 | **일간 · 이용수 순** — 기간 버튼 배열(일→주→월)의 첫 값과 같습니다 |
| 기준 전환 | 이용수(기본) · 좋아요 순 · 리뷰 점수 순 · 리뷰 많은 순 |
| 최소 표본 | 리뷰 점수 순은 **리뷰 50개 이상**만 순위에 포함 — 미달 캐릭터는 목록에서 제외 |
| 0건 제외 | 선택한 기간의 이용수가 0건이면 이용수 순위에서 뺍니다 |

「표시」 랭킹 화면의 기간·기준 전환 버튼, ⓘ 도움말("리뷰 50개 미만은 점수 순위에서
제외됩니다" 등 기준 안내).

### 8-4. 동률 체인 (모든 정렬 공통)

**선택 기준 → 이용수 → 좋아요 수 → 캐릭터 ID** 순으로 비교합니다. 어떤 데이터에서도
순서가 하나로 결정됩니다. 랭킹·홈 섹션·카테고리 목록 전부 이 체인을 씁니다.

체인의 **이용수는 월간(최근 30일)** 값입니다. 창이 닫혀 있어야 오래전 인기가 순서를
영원히 붙잡지 않습니다. 선택 기준이 따로 없는 목록은 이 고리가 그대로 1차 키가 됩니다.

### 8-4-1. 캐릭터 카드 구성

목록 카드는 **이미지 자리 · 페이지 제목 · 보조 설명 · 제작자** 네 줄이며, 이미지는 **세로형(3:4)**
입니다(SUT에서는 캐릭터 이름 텍스트로 대신합니다).

- 좋아요·리뷰·이용수 같은 **지표는 카드에 두지 않습니다** — 서비스 화면을 그대로 두고, 정렬
  근거를 확인할 때만 테스트 설비(디버그 콘솔)에서 켭니다. 켜면 카드에 한 줄이 붙고 랭킹에서는 그
  자리에 선택한 정렬 기준값이 나옵니다
- 랭킹의 순위 번호는 지표 표시와 무관하게 항상 보입니다

### 8-5. 홈 섹션 선정식

| 섹션 | 선정식 |
|---|---|
| 떠오르는 신작 | 생성 **60일** 이내(기준일 기준) ∧ 월간 이용수 1건 이상 ∧ 주간 이용수 **상위 5** |
| 지금 뜨거운 | 주간 이용수 1건 이상 ∧ 주간 이용수 **상위 5** |
| 추천 캐러셀 | 최대 7개 — 월간 이용수 순(동률은 §8-4), 초과 데이터 시 7개까지만 |
| 최근 대화한 캐릭터 | 대화 이력 없으면 섹션 미노출 |

떠오르는 신작에서 **두 창은 서로 다른 일을 합니다** — 월간은 모수를 거르고(이용자가 아예
없는 캐릭터를 뺍니다) 주간은 순서를 만듭니다. 그래서 갓 등록되어 아직 이용자가 없는
캐릭터는 노출되지 않고, 이번 주에 오르고 있는 캐릭터가 위로 갑니다.

두 섹션의 모수 조건이 이용수 0건을 빼는 이유는 섹션의 뜻과 어긋나는 카드가 상위에 오르면
선정식을 화면으로 검증할 수 없기 때문입니다. 조건에 맞는 캐릭터가 없으면 섹션 자리에
0건 안내가 놓입니다.

「표시」 추천 탭의 섹션 카드 배열 — **카드 순서 자체가 기대값**입니다.

### 8-6. 카테고리

**카테고리는 페이지(작품)의 속성입니다** — 캐릭터가 따로 카테고리를 갖지 않습니다.
한 작품이 카테고리를 여러 개 가지며, 화면에서는 구분 없이 `#` 칩으로 함께 보여 줍니다.

| 항목 | 값 |
|---|---|
| 홈 칩 구성 | **로맨스 · 판타지 · 일상** (3종 고정) — 작품 카테고리 배열의 **첫 항목이 대표**이며 이 셋 중 하나입니다 |
| 카테고리 인기 신작 | 8-5 떠오르는 신작과 같은 식, 모수만 그 카테고리를 가진 작품 |
| 함께 보는 카테고리 | 로맨스 #집착·#소꿉친구·#계약연애·#후회 / 판타지 #회귀·#빙의·#이세계·#능력 / 일상 #힐링·#학원물·#직장·#동거 — 칩 카테고리와의 **AND 필터**, 결과 0건 안내 |
| 전체 목록 정렬 | 대화순(누적 이용수 순) / 최신순(생성일) |

### 8-7. 검색·좋아요·스크랩

- 키워드 검색은 **페이지 제목과 페이지 카테고리**의 부분일치이며 결과 0건 안내 문구를 표시합니다. 제작자 검색은 실측에 있으나 소셜이 제외 영역이라 넣지 않습니다
- 좋아요·스크랩은 토글 상태가 유지되고 MY 활동 목록에 반영됩니다. 정렬에 쓰는 좋아요 수 =
  시트 기본값 + 계정의 토글 반영입니다

### 8-8. 캐릭터 페이지

카드를 누르면 열리는 화면이며, 대화는 여기서만 시작합니다.

캐릭터 페이지는 **작품 층과 캐릭터 층**으로 나뉩니다 — 제작자가 만든 작품 안에 캐릭터가 있고,
유저는 자기 프로필을 골라 그 캐릭터와 대화합니다.

| 층 | 항목 | 상한 |
|---|---|---|
| 작품 | 페이지 제목 | **20자** |
| 작품 | 보조 설명 | **30자** |
| 작품 | 스토리 블록 | 상한 없음 — 길어지면 블록을 나눠 붙입니다 |
| 작품 | 페이지 카테고리(여러 개) | 개수 제한 없음 · 첫 항목이 홈 칩 대표 |
| 캐릭터 | 이름 · 한 줄 설명 · 상세 설명 | 상한 없음(표시만) |

제작자 입력 화면은 만들지 않으므로(캐릭터 저작은 제외 영역) 이 값들은 시트 데이터이며,
상한은 테스트 설비(디버그 콘솔)의 입력에서 지킵니다.

| 요소 | 규칙 |
|---|---|
| 표시 순서 | ① 상단 바(뒤로가기·페이지 제목) → ② 캐릭터 이미지(세로형) → ③ 페이지 제목 → ④ 보조 설명 → ⑤ 작업자 → ⑥ 지표(+좋아요·스크랩) → ⑦ 페이지 카테고리 칩 → ⑧ 스토리 블록 → 캐릭터 소개(구분선으로 이름·한 줄 설명·상세 설명·시작 상황·첫 메시지) → ⑩ 출시일·최종 업데이트(버전) → ⑪ 작품 추천 → ⑫ 대화방 목록과 [프로필 선택]·[대화 시작] |
| 스토리 블록 | 길어지면 작업자가 나눠 붙입니다(500자 안팎 권장) — 화면은 블록마다 단락을 나눠 그립니다 |
| 지표 | **페이지에서는 늘 보입니다.** 카드에서만 감추고 테스트 설비로 켭니다(§8-4-1) |
| 시작 상황 | 제작자가 정한 상황을 **표시만** 합니다 — 유저는 고르지 못하고 그 상황으로 시작합니다. 캐릭터당 하나입니다 |
| 하단 버튼 | 그 캐릭터와의 대화방이 **없으면** 「프로필 선택 + 대화 시작」, **있으면** 「대화방 목록 + 새 대화 시작」 |
| 대화방 목록 | 방마다 프로필·진행 상태를 함께 표시하고, 고르면 그 방으로 재진입합니다 |
| 한도 | 캐릭터당 대화방 수는 §6이 정본이며, 찼을 때의 삭제 흐름도 §6을 따릅니다 |
| 게이팅 | 언세이프 캐릭터는 소개·첫 메시지·시작 상황을 숨기고 막힌 사유만 보입니다(§9) |

「표시」 캐릭터 페이지 상단(제작자·현황·출시일/업데이트)과 하단 고정 버튼.

## 9. 세이프티·게이팅

- 언세이프 콘텐츠: 미인증·미성년에게 목록 블러+상세 숨김. 미성년은 해제 수단이 없습니다
- 세이프티 필터 토글: 성인 인증 계정에만 노출(MY 콜아웃), ON이면 언세이프를 홈에서 숨깁니다
- 입력·출력 필터와 우회 방어·프롬프트 누출 차단은 **게이팅 계층의 검증**입니다 — 모델
  자체의 안전성 검증이 아님을 산출물에 명시합니다. 금칙 코퍼스는 추상 토큰(`[BLOCKED_TERM_A]`)만 씁니다

### 9-1. 필터 규칙 (2026-08-03 확정)

**판정은 추상 토큰으로만 합니다.** 자연어 패턴은 어디까지가 위반인지 경계가 흔들려 기대값을
적을 수 없고, 실제 탈옥 문자열을 저장소에 넣지 않는다는 방침(§저작권)과도 맞습니다.

| 토큰 | 쓰임 |
|---|---|
| `[BLOCKED_TERM_A~C]` | 금칙어 — 입력·출력 양쪽에서 걸립니다 |
| `[JAILBREAK_A]` | 우회(탈옥) 시도 — 입력에서만 |
| `[INJECT_A]` | 지시문 주입 — 프로필 설명란과 입력 양쪽 |
| `[LEAK_PROMPT]` | 내부 지시를 캐묻는 입력 — 정해진 거절문만 돌려줍니다 |

- **우회 방어는 정규화로 합니다** — 대조 전에 공백·특수문자를 지우므로 `[BLOCKED_ TERM_A]`나
  `[B-L-O-C-K-E-D_TERM_A]`도 같은 것으로 봅니다. 토큰을 쪼개 넣는 것이 우회 시도의 형태이고,
  그것을 막는 것이 이 노드입니다

**입력 차단은 보낼 때 합니다.** 치는 동안에는 막지 않고 [전송]·[저장]을 누를 때 걸러 사유를
알립니다 — 자동화가 값을 주입해 넣는 경로와 사람이 치는 경로가 같은 지점에서 걸려야
검증 지점이 하나로 모입니다.

- 차단된 전송은 **아무것도 소비하지 않습니다** — 재화·턴·대화수 어디에도 흔적이 없습니다
  (§3의 실패 규칙을 그대로 받습니다). 친 내용은 입력창에 남습니다

**출력은 차단합니다(마스킹하지 않습니다).** 단어만 가리는 것은 욕설 필터의 방식이고, 안전
계층은 그 응답을 내보내지 않는 쪽이 맞습니다. 다만 응답이 시드로 정해져 있어 그대로 막으면
같은 턴에서 영원히 진행하지 못하므로 두 층으로 둡니다.

| 층 | 규칙 |
|---|---|
| ① 대체 | 금칙 토큰이 든 후보는 **쓰지 않고 그 턴의 다른 후보로 넘어갑니다.** 걸러졌다는 사실은 화면에 표기합니다 |
| ② 차단 | 그 턴의 후보가 전부 금칙이면 **응답을 내보내지 않고** 안내만 띄웁니다. 턴·재화·호감도 아무것도 소비하지 않습니다 |

- ①은 지운 기억을 참조하는 후보를 건너뛰는 규칙(§7-1)과 같은 자리에서 함께 판정합니다
- **프롬프트 누출**은 응답을 만들지 않고 정해진 거절문을 돌려줍니다 — 내부 지시·시스템
  프롬프트·mock 세트의 내용이 응답에 나오면 실패입니다. **후보를 고르는 단계로 가지 않으므로**
  그 턴의 후보가 전부 금칙이어도 결과가 같습니다. 거절문은 대사가 아니라 상태를 만들지
  않지만(호감도 0·기억 없음), 응답을 돌려준 한 턴이므로 재화는 소비합니다
- **설명란 주입**은 프로필 저장에서 막고, `setData()`로 값이 들어온 경우를 위해 대화
  경로에서 한 번 더 봅니다 — 어느 경로로 들어와도 같은 결과여야 합니다(§2와 같은 원칙)
- 「표시」 입력 차단 안내(사유별), 응답 대체·차단 표기, 프로필 저장 시 주입 차단 안내
