# qa-lab-miyonchat — 도메인 판단 기록 (addition-rationale)

## 0. 문서 지위

- **판단 기록**입니다. 확정안이 아니므로 TC 기대값으로 쓰지 않습니다 — 값의 정본은 트리와
  `design/`입니다
- §1은 레퍼런스에 없어 직접 세운 노드(ADD)의 근거, §2는 값이 공개되지 않아 직접 정한
  수치의 근거입니다. "그 숫자는 왜 그렇게 정했나요?"의 답을 모으는 곳입니다
- SUT 구조 판단은 이 파일이 아니라 `sut-rationale.md`에 있습니다

## §1 노드 보강 근거 (ADD 13건)

| 노드 | 근거 |
|---|---|
| 세션 만료 처리 | 3사 모두 만료 동작이 실측 불가(`?`)였지만, 만료는 세션 검증의 반쪽이라 규칙을 직접 세웠습니다. 시간 대기 없이 재현하도록 트리거를 테스트 설비로 두는 것까지가 한 묶음입니다 |
| 로그아웃 후 데이터 잔존 차단 | 3사 실측 불가 구간. 잔존은 화면에 안 보이는 결함이라 상태 조회 훅 검증의 대표 재료로 편입했습니다 |
| 계정 전환 격리 | 조사 자료가 없는 영역이지만, 인증 플래그가 상태를 지배하는 SUT 구조에서 계정 경계는 격리 검증의 1번 경계입니다 |
| 보호 화면 직접 접근 차단 | 딥링크 동작이 3사 미확인. URL 직접 진입은 웹 SUT에서 가장 싼 우회 경로라 차단 규칙을 명시했습니다 |
| 알림 목록 표시 | 발생 로직 없이 표시 반영만 검증하는 전시용 노드 — 데이터 주입→표시 정합의 최소 사례로 편입했습니다 |
| 이용수 집계 규칙 | 플레이툰 가이드의 "하루 1회, 중복 없음" 서술을 실집계 규칙(유저×캐릭터×날짜 dedup)으로 구체화 — 집계를 표시값이 아니라 이벤트 테이블 실계산으로 검증하기 위해서입니다 |
| 연타 이중 차감 방지 | 크랙의 방어 문구("이미 사용중입니다")로 존재는 확인되나 규칙이 비공개 — 1회만 차감으로 직접 확정했습니다 |
| 충전 실패 롤백 | 실패 경로는 어느 레퍼런스도 공개하지 않는 구간이지만, 결제 mock의 검증 가치가 성공 반영보다 실패 무변화에 있어 편입했습니다 |
| 설명란 프롬프트 주입 차단 | 조사에 입력측 주입 필터 서술이 없어 게이팅 계층 규칙으로 직접 세웠습니다. 모델 내성 검증이 아님을 함께 명시합니다 |
| 슬롯 간 격리 | 화면으로 확인 불가한 영역(조사 자료 없음). save-leak 결함 주입과 짝을 이루는 검증 재료입니다 |
| 삭제 기억 재등장 차단 | 조사에는 결함 우려로만 존재 — ghost-memory 주입과 짝을 이루도록 규칙화했습니다 |
| 리뷰 점수순 최소 표본 (v1.1) | 소표본 평점 왜곡(리뷰 1개 5점이 1위) 방지. 실서비스가 흔히 갖는 신뢰도 규칙이며 경계 TC 재료가 됩니다 |
| 대화수 표시 정합 (v1.1) | 플레이툰 실측에서 대화수 갱신 시점이 모호(페이지 로드 시 반영)함을 확인 — 우리 SUT는 즉시 반영을 못 박아 "표시=내부 상태" 검증으로 바꿨습니다 |
| 미로그인 진입 = 홈 직행 (v1.2, REF→ADD) | 조사에서는 AI 챗 3사가 모두 "미로그인 → 로그인 화면"이라 초판은 그 값을 REF로 채택했습니다. 그런데 문이 하나뿐이면 게이팅 검증이 "로그인했는가"로 끝납니다. 공개 범위(탐색·검색·카드 상세·커뮤니티)와 보호 범위(대화·채팅·MY·재화·좋아요)의 경계를 만들면 **경계마다 차단·유도·복귀가 검증 대상이 되어** 금칙 케이스가 크게 늘어납니다. 조사값을 버리고 직접 정한 것이므로 출처를 ADD로 바꿨습니다 |
| 미로그인 보호 동작 차단 (v1.2) | 위 결정의 짝입니다. 차단만으로는 부족하고 **동작이 실제로 수행되지 않았는지**를 함께 봐야 합니다 — 로그인 화면은 떴는데 좋아요가 이미 반영됐다면 게이트가 표시만 하는 셈입니다 |
| 언세이프 게이트에 미로그인 상태 추가 (v1.2) | 미로그인과 미성년은 둘 다 언세이프를 못 보지만 **해제 가능 여부가 다릅니다**(미로그인은 로그인하면 풀리고 미성년은 수단이 없음). 같은 화면 상태에서 갈라지는 두 경로라 게이팅 TC의 좋은 대비쌍이 됩니다 |

## §2 수치 확정 근거

| 대화에서 기억 등록 | ADD | 2026-08-03 사용자 제안. 조사한 3사 기록에는 없습니다 — 플레이툰의 장기 기억은 자동 축적이고 유저가 특정 메시지를 골라 기억시키는 동선은 실측 표에 잡히지 않았습니다. 다만 기억이 AI가 알아서 쌓는 길뿐이면 「유저가 정한 것이 AI 판단보다 우선」이라는 이 영역의 축이 고정·삭제로만 서서, 기억을 **만드는** 쪽은 검증 대상이 되지 않습니다. 유저 등록 경로를 두어 그 축을 만들기·지키기·지우기 셋으로 채웁니다 |
| 상태 값 고정 대상 = 감정 온도·호칭 | ADD | 관계 단계·호감도는 엔딩 판정의 근거라 고정하면 판정과 표시가 어긋나 기대값이 갈립니다. 표시·응답에만 쓰이는 두 값으로 대상을 좁혀 「고정값이 자동 계산보다 우선」을 검증 가능한 범위에 둡니다 |
| 말투 지정·자연어 지시 제외 | 제외 근거 | 2026-08-03 사용자 확정. 말투는 응답 어미 전체를 바꿔 대사 세트가 두 벌 필요한데, 「고정값이 자동 계산보다 우선」은 호칭에서 이미 응답으로 확인되어 검증 축이 늘지 않습니다. 자연어 지시(「반말 써 줘」)는 실제 LLM이 없어 불가하며, 알아듣게 만들면 같은 시드에서 응답이 갈라져 결정성이 깨집니다. 두 사유를 트리 제외 영역·system-spec §7-2·SUT 화면(현재 상태 패널·대화방 안내) 세 곳에 남겼습니다 |
