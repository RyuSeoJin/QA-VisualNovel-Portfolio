# qa-lab-miyonchat — SUT 판단 기록 (sut-rationale)

SUT 청사진(`sut-design/…-sut-blueprint.md`)의 짝 문서입니다. 청사진은 구현자가 읽는 선언만 담고,
그 선언을 고른 이유는 전부 여기에 모입니다. 도메인 판단(ADD 노드·수치의 근거)은 이 파일이
아니라 `addition-rationale.md`에 있습니다 — 성격이 다른 판단을 섞지 않습니다.

## §1 구조 판단

| 결정 (청사진 위치) | 이유 |
|---|---|
| 화면 구성을 고정 세트로 못 박음 — 전역 셸+탭 화면·전환 화면·패널·테스트 콘솔 (§1) | 일정이 무너지는 최대 지점이 "SUT 꾸미기"라서, 화면 구성을 처음부터 못 박아 확장 압력을 차단합니다. 검증 대상은 기능이지 화면 수가 아닙니다. (v1.0 동기 개정 전 표현은 "화면 5개+패널 3개" — 확정안의 셸 구조를 반영하며 세트 내용만 바뀌고 고정 원칙은 유지) |
| 로그인을 계정 A(성인 인증)/B(미인증) 버튼 2개로 단순화 (§1 로그인 화면) | 실제 소셜 로그인은 흉내만 낼 수 있어 검증 가치가 없고, 진짜 검증 가치는 인증 플래그가 상태를 지배하는 로직에 있습니다. 두 계정의 플래그 차이만으로 게이팅·계정 격리 TC가 전부 성립합니다 |
| 재화를 계정 스코프에 배치 — 분기 방 간 공유 (§2) | 실존 서비스(플레이툰)에서 재화는 방과 무관한 계정 자산입니다. 방 스코프에 넣으면 분기 생성으로 재화가 복제되는 비현실적 구조가 됩니다 |
| 분기 세이브를 "원본 보존 + 방 복제"로 구현 (§2) | 플레이툰 타임머신이라는 실존 구현을 채택했습니다(REF). 슬롯 덮어쓰기형보다 격리 검증 시나리오(원본/분기 독립성)가 풍부해집니다 |
| AI 응답 재생성 시 이전 응답의 상태 변화를 취소 (§2) | 재생성의 전형적 결함이 상태 이중 반영(호감도 중복 가산)이라서, 취소·재계산을 규칙으로 못 박아야 그 결함이 검증 가능한 기대값이 됩니다 |
| `__VN__.expireSession()` 추가 (§3-2) | 세션 만료는 화면 요소가 아니라 시간 조건이라 테스트가 일으킬 수단이 없습니다. 시간 대기는 테스트를 느리고 불안정하게 만들므로 명시적 트리거로 대체합니다 |
| data-testid에 화면 접두(s1~p3) (§3-1) | 자동화 파일이 영역 단위로 나뉘므로, 셀렉터만 보고 어느 화면·어느 파일인지 대응되게 합니다 |
| 계측 수치를 품질 지표로 서술 금지 (§4) | mock의 변주 폭을 우리가 작성했으므로, 준수율 같은 수치는 우리가 만든 분포를 되읽는 것입니다. 지표로 쓰면 "mock인데 92%가 무슨 의미냐"는 반문에 무너집니다 |
| 대화방을 셸 밖 전체 화면으로 (§1) | 입력창·패널 버튼이 하단에 상주해 하단 내비와 조작 영역이 겹치므로, 대화는 전용 화면으로 빼고 뒤로가기로 셸에 복귀시킵니다 |
| 채팅 탭을 방 목록·재진입 화면으로 (§1) | 방 전환이 대화방 헤더에만 있으면 셸에서 기존 방으로 들어갈 경로가 없습니다. 그리고 분기 방이 목록에 드러나야 타임머신 구조의 원본/분기 독립이 화면에서도 확인됩니다 |
| 재화/충전 패널·간편 프로필 패널을 상단 바 전역 진입으로 (§1) | 재화 부족은 대화 중에 발생하고, 미션 허브는 확정안이 상단 바 간편 프로필로 지정했으므로 특정 탭에 묶지 않습니다. 대화방 헤더의 잔액 표시에서도 재화/충전 패널이 열려야 잔액 0 차단→충전 안내 흐름이 화면 이동 없이 이어집니다 |
| 디버그 콘솔 진입 버튼을 전 화면 공통 우하단 고정으로 (§1) | 상태 스위처가 미로그인 전환을 포함하므로 셸 밖(로그인 화면·대화방)에서도 열려야 하고, 서비스 화면과 테스트 설비가 섞여 보이지 않도록 오버레이로 격리합니다 |
| 시트 데이터를 정적 데이터에서 분리해 스코프 신설 (§2) | 데이터 주입이 생기면서 캐릭터 속성 등의 "빌드 시 고정" 전제가 깨졌으므로 가변 스코프로 분리합니다. 쓰기 경로를 디버그 콘솔과 `setData()` 둘로 제한해 상태의 출처가 항상 추적되게 합니다 |
| `setData()`와 디버그 콘솔이 같은 저장소를 쓰도록 (§3-4) | 사람 검증과 자동화가 다른 데이터를 보면 실패 재현이 어긋나므로, 경로만 둘이고 저장소는 하나입니다 |
| 세이프티 필터 토글을 홈 화면에서 MY 탭 콜아웃으로 이동 (§1, 2026-08-02 사용자 화면 구상 반영) | 플레이툰 실측이 MY 배치라 REF와 일치시키고, 홈은 목록·게이팅 표시에 집중시킵니다. ON이면 홈에서 숨긴다는 트리의 행동 규칙은 그대로입니다 |
| 간편 프로필 패널 미션 허브에 보유 재화·히스토리를 집약하고 MY 탭에도 잔액 표시 (§1, 같은 반영) | 재화를 얻는 곳(미션)과 현황을 보는 곳이 갈라져 있으면 수령→잔액 반영 확인이 화면을 오가야 하므로 진입점을 이중화합니다. 표시 데이터는 재화/충전 패널과 동일 원본을 읽어 정합 검증 대상이 됩니다 |
| 홈 서브탭을 필터 칩 구조로 — 카테고리 3종이 상위 칩 (§1, 같은 반영) | 플레이툰 실측(홈 칩 6종)과 같은 계열입니다. 배치만 바뀌고 기능(태그 일치 노출·칩 최대 3)은 트리 그대로라 트리 개정 없이 청사진에서 처리합니다 |

## §2 타당성 검증 기록 (2026-08-01)

구현 범위 기획안(여정 축 10영역)을 SUT 청사진 초안의 화면 5개·상태 모델 4스코프에 배치해
검증했습니다.

- **결과: 10영역 전부 배치됨. 기획안 수정이 필요한 노드 없음** (배치표는 청사진 §1-1)
- 유일한 보강: 세션 만료 트리거 부재를 발견해 `expireSession()` API를 추가 — 기획 변경이
  아니라 테스트 인터페이스 보강입니다
- 이 검증으로 기획안은 트리 v1.0 반영 대기 상태가 됐습니다(반영 시 구현 범위 확정)

## §3 트리 v1.0 동기 개정 기록 (2026-08-01)

트리 v1.0 확정으로 초안의 화면 맵(화면 5개·탭 3종)이 확정안(전역 셸+하단 내비)과 어긋나게
되어, 청사진을 개정하고 초안 → 확정으로 전환했습니다.

- **배치 재검증 결과: 트리 v1.0 구현 범위 전 노드가 개정 화면 맵에 배치됨. 기획 수정 없음**
- 신설 화면(채팅·MY·커뮤니티·내 작품 탭과 간편 프로필 패널·디버그 콘솔)은 전부 확정안(change-log 2026-08-01 시작 세트 확장)의 항목을
  배치한 것이며, 이 개정에서 새 기능을 만들지 않았습니다
- 테스트 인터페이스는 데이터 주입(§3-4)이 더해져 네 갈래가 됐습니다 — 확장의 근거는
  change-log의 테스트 설비 확정 항목입니다
