## v1.9 (2026-08-03) — 고정을 두 노드로 가르고 기억 등록을 편입 (123 → 125노드 · 제외 +2)

「핀 고정 우선」 한 노드가 서로 다른 두 기능을 덮고 있었습니다. 실측(플레이툰)의 핀은
**현재 상태 대시보드의 항목 값**에 붙는 것인데("항목 값 수정 후 고정 → AI 자동 계산 시에도
고정값이 우선"), 노드가 메모리 영역에 있어 구현에서 **기억 항목 고정**으로 읽혔습니다. 둘 다
필요한 기능이라 노드를 갈랐습니다.

- 메모리/컨텍스트 > **「핀 고정 우선」 → 「상태 값 고정」** / 수정 / 실측의 대상이 현재 상태
  항목 값임을 노드에서 읽히게. 대상 항목은 design에서 확정 / 변경 전: "유저가 고정한 값이
  AI 자동 갱신보다 우선"
- 메모리/컨텍스트 > **기억 고정** / 추가(REF) / 기억의 자동 정리(장면 종료 시 간략화)를 유저가
  막는 기능. 위 노드에서 갈라져 나옴 / 없던 노드
- 메모리/컨텍스트 > **대화에서 기억 등록** / 추가(ADD) / 사용자 제안. 지금은 기억이 AI가 알아서
  쌓는 길뿐이라 유저가 "이건 기억해 둬"라고 넣는 동선이 없었습니다. 조사한 3사 기록에는
  없는 기능이라 ADD이며 근거는 `rationale/…-addition-rationale.md` / 없던 노드
- 제외 영역 > **말투 지정** / 추가 / 실측 대시보드에는 「호칭/말투」가 한 항목이지만 말투는
  응답 문장 전체의 어미를 바꿔 대사 세트가 두 벌 필요합니다. 「고정값이 자동 계산보다 우선」은
  호칭에서 이미 응답으로 확인되어 검증 축이 늘지 않으므로 제외 / 없던 항목
- 제외 영역 > **자연어 지시 이해** / 추가 / 「반말 써 줘」처럼 대화로 캐릭터의 행동을 바꾸는
  것. 실제 LLM이 없고 알아듣게 만들면 같은 시드에서 응답이 갈라져 결정성이 깨집니다.
