# qa-lab-miyonchat 용어집 — 이 프로젝트에서만 통하는 말과 그 정본 자리

이 프로젝트의 **고유명사 색인**입니다. 화면 이름·재화 이름·테스트 설비처럼 「qa-lab-miyonchat」을
지우면 뜻이 성립하지 않는 말을 모았습니다. 범용 QA 용어는 중앙
[qa-dictionary](../../project-process/qa-dictionary.md)에 있습니다 — 배치 기준은 「정의 문장에서
프로젝트 이름을 지워도 성립하는가」입니다.

**정의를 새로 쓰는 곳이 아닙니다.** 한 줄 요약과 정본 자리만 적습니다. 값이 궁금하면 정본을
열어야 하며, 두 곳에 적으면 언젠가 어긋납니다. 정본 경로는 프로젝트 폴더
(`projects/qa-lab-miyonchat/`) 기준입니다.

## SUT와 화면

| 용어 | 한 줄 요약 | 정본 |
|---|---|---|
| MiyonChat | 이 프로젝트가 직접 만든 검증 대상. 미연시 AI 챗을 단일 HTML+JS로 구현한 것이며, 역분석 대상(플레이툰 등)과 다릅니다 | `spec/sut-design/…-sut-blueprint.md` §1 |
| 전역 셸 | 상단 바 · 탭 화면 · 하단 내비 · 푸터로 이루어진 공통 틀. **대화방은 이 밖의 전체 화면**이라 하단 내비가 없습니다 | 청사진 §1 |
| 홈 화면 | 진입점이자 탐색의 시작. 미로그인으로도 열람 범위를 둘러볼 수 있습니다 | 청사진 §1 · `spec/design/…-system-spec.md` §8-5 |
| 캐릭터 페이지 | 작품과 캐릭터를 두 층으로 보여 주는 화면. 대화방 목록과 한도 안내가 여기 붙습니다 | system-spec §8-8 |
| 대화 프로필 화면 | 유저 페르소나를 만들고 고르는 화면. 대화 시작 시 여기서 고른 프로필이 방에 고정됩니다 | system-spec §2 |
| 대화방 | 캐릭터와의 대화가 진행되는 화면. 캐릭터마다 여러 개를 두며 방마다 프로필·전개가 갈립니다 | system-spec §5·§6 |
| 세이브/로드 패널 · 현재 상태 패널 | 대화방 안에서 열리는 두 패널. 앞은 시점 슬롯을, 뒤는 호감도·관계 단계·기억을 다룹니다 | system-spec §6·§7 |
| 간편 프로필 패널 | 상단 바에서 여는 계정 요약 자리. 잔액과 미션 수령이 여기 있습니다 | system-spec §3 |
| 로그인 모달 · 로그인 화면 | 로그인 유도의 두 갈래. **보여 줄 화면이 있으면 모달**을 덮고, 로그인 필요 화면 URL로 직접 들어와 뒤에 깔 화면이 없을 때만 로그인 화면을 띄웁니다 | system-spec §1-1 |
| 스텁 | 화면 자리와 이동만 있고 기능이 없는 탭(커뮤니티·내 작품). 구현하지 않았다는 사실 자체를 화면에 표기합니다 | 청사진 §1·§5 |

## 게이팅과 세션

| 용어 | 한 줄 요약 | 정본 |
|---|---|---|
| 게이팅 상태 | 미로그인 · 본인인증 미진행 · 성인 인증 · 미성년 · 세션 만료. TC 시트의 상태 열과 골격의 `[상태:]` 선언이 이 값을 씁니다 | system-spec §1-1 |
| 미로그인 열람 / 로그인 필요 | 로그인 없이 볼 수 있는 범위와 막히는 동작. **예전에 「공개/보호」로 부르던 것**이며 화면 용어는 이쪽입니다 | system-spec §1-1 |
| 성인 계정 · 미성년 계정 | 로그인 화면에서 고르는 두 계정. 「계정 A/B」 같은 내부 식별자를 화면·문서에 쓰지 않습니다 | system-spec §1-1 · `rules/tc-sheet-format.md` §내부 식별자 |
| 본인인증 미진행 ↔ 미성년 | 화면상 같아 보이지만 **해제 가능성이 정반대**입니다 — 앞은 인증하면 풀리고 뒤는 어떤 수단으로도 풀리지 않습니다. 게이팅 검증의 축입니다 | system-spec §1-1 |
| 언세이프 | 성인에게만 열리는 콘텐츠. 미인증·미성년에게는 목록 블러와 상세 숨김으로 막힙니다 | system-spec §9 |
| 세이프티 필터 토글 | 성인 인증 계정에만 보이는 스위치. 켜면 언세이프를 홈에서 감춥니다 | system-spec §9 |
| 막힌 동작 이어받기 | 로그인이 없어 막힌 동작을, 로그인한 뒤 그대로 이어서 수행하는 규칙. **막을 때는 아무것도 하지 않습니다** | system-spec §1-1 |
| 세션 지속 | 새로고침·재진입에서 로그인 상태가 유지되는 것. 저장 범위는 **계정 스코프뿐**이며 시트 데이터와 화면 보기 상태는 저장하지 않습니다 | system-spec §1-3 |

## 도메인 값

| 용어 | 한 줄 요약 | 정본 |
|---|---|---|
| 캔디 · 크리스탈 | 무료 재화와 유료 재화의 이름. 실서비스 명칭을 쓰지 않으려고 직접 지은 말입니다 | system-spec §3 |
| 혼합 차감 | 캔디를 먼저 쓰고 부족분을 크리스탈에서 빼는 소모 방식. 히스토리에 지갑별로 두 줄이 남습니다 | system-spec §3 |
| 데일리 미션 · 웰컴 미션 | 재화를 주는 두 갈래. 달성 판정은 만들지 않았고 검증 대상은 수령·중복 차단·잔액 반영입니다 | system-spec §3 |
| 호감도 · 관계 단계 | 대화로 오르내리는 수치와 그 구간 이름(경계·호기심·애착·운명). 하한은 0이며 상한은 없습니다 | system-spec §4-1 |
| 엔딩 판정 | 굿·노멀·배드를 가리는 규칙. **검사 시점**(10턴 이후 5턴마다)에는 굿만 나오고 배드는 mock 경로 **종점**에서만 나옵니다 | system-spec §4-2 |
| 되돌림 | 최신 교환에만 열리는 편집·삭제·AI 응답 재생성. 과거 턴에는 「이 지점에서 분기」만 열립니다 | system-spec §5-1 |
| 대화방 ↔ 시점 슬롯 | 세이브의 두 층. 방은 「다른 프로필·다른 전개의 줄기」를, 슬롯은 「그 줄기 안의 되돌아갈 지점」을 담습니다 | system-spec §6 |
| 로드 갈래 | 슬롯을 불러올 때 고르는 둘 — 이 방에 덮어쓰기 / 새 방으로. 뒤가 곧 분기 생성이며 대화방 한도를 함께 받습니다 | system-spec §6 |
| 기억 | 캐릭터가 대화에서 붙잡아 둔 유저 정보. 핀으로 고정하면 자동 갱신이 덮지 못하고, 지운 기억이 재등장하면 실패입니다 | system-spec §7-1 |
| 단기 맥락 창 | 응답에 반영되는 최근 턴의 범위. 창 밖 정보가 반영되면 실패이며 경계는 결정적으로 검증합니다 | system-spec §7 |
| 추상 토큰 | `[BLOCKED_TERM_A]`·`[JAILBREAK_A]`·`[INJECT_A]`·`[LEAK_PROMPT]`처럼 판정에만 쓰는 표식. 실제 금칙·탈옥 문자열을 저장소에 넣지 않으려는 선택입니다 | system-spec §9-1 |
| mock 응답 · 시드 | 응답을 모델 대신 정해 둔 세트와, 같은 입력에 같은 응답을 보장하는 고정 값입니다 | `spec/sut-design/…-mock-llm-spec.md` |

## 테스트 설비

| 용어 | 한 줄 요약 | 정본 |
|---|---|---|
| 디버그 콘솔 | 화면(`#app`) 밖에 있는 테스트 설비. 상태 전환·데이터 편집·실패 스위치를 사람이 쓰는 자리이며, 여기서 무엇을 눌러도 화면은 그대로 남습니다 | 청사진 §4-2 |
| 상태 스위처 | 게이팅·세션 상태를 만들어 내는 콘솔 조작. 자동화의 `gate` 픽스처가 같은 자리를 씁니다 | 청사진 §4-2 · `automation/tests/conftest.py` |
| 데이터 시트 | 홈·랭킹 등이 읽는 표 데이터. 사람은 콘솔 UI로, 자동화는 `setData`로 같은 저장소에 씁니다 | 청사진 §3-4 |
| 가상 시계 | 기준일을 옮겨 날짜 의존 동작(데일리 미션 등)을 만드는 설비 | system-spec §8-1 |
| `window.__VN__` | SUT가 테스트에 여는 상태 조회·제어 API. **상태를 바꾸는 것은 화면을 자동으로 갱신하지 않습니다** — 갱신 시점을 도구가 정하면 「데이터는 바뀌었는데 화면이 안 따라오는」 결함을 검증할 수 없습니다 | 청사진 §3-2 |
| `?seed=` · `?inject=` | 실행 조건을 URL로 주는 파라미터. 앞은 응답 경로 고정, 뒤는 결함 주입이며 결함은 **URL로만** 켭니다 | 청사진 §3-3 |
| `?v=` | `index.html`이 CSS·JS를 부를 때 붙이는 캐시 무효화 번호. 올리지 않으면 고친 것이 반영되지 않습니다 | `qa-lab-miyonchat-change-log.md` §SUT를 이어서 만들 때 |
| 주입 결함 | `gate-bypass`(라우팅 가드·게이팅) · `save-leak`(슬롯 복사 계층) · `ghost-memory`(지운 기억 판정) · `persona-drift`(응답의 호칭 치환). 일부러 심어 두고 담당 TC가 잡는지 봅니다 | `spec/sut-design/…-fault-injection.md` §2 |
| `SUT_BUILD` · RC 표기 | `sut/js/data.js`가 들고 있는 빌드 좌표(`PC웹_Ver1.0_Dev_RC25` 꼴). 슬라이스를 마칠 때마다 올리며 이슈의 확인 버전이 이 값입니다 | `sut/js/data.js` · change-log |
