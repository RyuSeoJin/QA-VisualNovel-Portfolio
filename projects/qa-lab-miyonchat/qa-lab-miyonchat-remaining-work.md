### 진행 방식 (2026-08-03 합의)

```
① 영역 하나 작성 → 형식·밀도 확인받기      ← 여기서 한 번 멈춥니다
② 나머지 9영역 작성
③ xlsx 생성 → Excel 오픈 검증
④ 결함 주입 매트릭스의 열 확정
```

①에서 멈추는 이유는, 100건 넘게 쓴 뒤에 「케이스 쪼개는 단위가 다르다」가 나오면 전부 다시
써야 하기 때문입니다. 규모는 영역 10개 × (정상 흐름 + 경계 + 금칙 + 격리)로 **90~130건**
안팎을 예상합니다 — 정확한 수는 써 봐야 압니다.

### 입력 형식이 바뀌었습니다 (2026-08-03 · `b8f8e7b`)

`tcs` 한 줄이 **11필드**이고 두 번째 값이 **트리 경로 배열**입니다. 케이스명은 경로 다음
칸에 놓이며, 생성 시 **실제로 쓰인 깊이까지만** 뎁스 열이 만들어집니다.

```json
["TC-XXX-001", ["탐색/발견","홈 탭","카테고리 탭","카테고리 칩 노출"], "칩 3개 표시",
 "사전조건", "1. 절차\n2. 절차", "기대결과 문장.",
 "결정적|확률적|루브릭|금칙", "High|Medium|Low", "선행 TC 또는 -", "대상 서비스", "비고"]
```

- 옛 형식(13필드·`d1`·`d2`·`d3`)도 읽히지만 새 형식으로 씁니다
- 규칙 정본은 `project-process/rules/tc-sheet-format.md`
