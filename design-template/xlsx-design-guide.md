# xlsx-design-guide — xlsx 산출물 서식 정본

## 0. 문서 지위

- 이 워크스페이스의 **모든 xlsx 산출물**(TC 시트·이슈 관리 시트·결과 시트)이 따르는 **서식
  규칙의 정본**입니다. 구조·컬럼 규칙의 정본은 `rules/tc-sheet-format.md`와 마스터의
  '명세서' 시트이며, 이 문서는 "어떻게 보이는가"만 담습니다
- 서식은 생성 스크립트(`scripts/build_tc_template_xlsx.py` 등)가 구현합니다. 산출물의
  서식을 손으로 고치지 않습니다 — 서식 변경은 이 문서 개정 → 스크립트 반영 → 재생성
  순서를 따릅니다
- 시트마다 다른 세부(틀 고정·배색 등)는 §4 시트별 옵션 표로 제어합니다 — 공통 기준은 전
  시트 강제, 옵션은 표의 한 칸을 고쳐 바꿉니다
- 확정: 2026-08-02 (사용자 기준 스타일 제시 → 예시 파일 검토로 확정)

## 1. 공통 기준 (전 시트 강제)

| 항목 | 값 |
|---|---|
| 폰트 | 맑은 고딕 |
| 헤더 행 | 배경 `#1F2A44` · 글씨 `#F3F3F3` bold · 중앙 정렬 |
| 데이터 행 | 배경 `#FFFFFF` · 글씨 `#000000` |
| 표 테두리 | 표 영역(헤더+데이터 행)만 `#999999` 실선 전체 테두리 |
| 표 밖 | 격자 없음 — 시트 격자선을 숨겨 흰 면으로 둡니다 |
| 여백 | A열·1행은 비웁니다(표는 B열부터) |
| 날짜 | `YYYY-MM-DD` |

## 2. 보조 톤

공통 기준 위에서 역할을 구분할 때만 씁니다.

| 용도 | 값 |
|---|---|
| 서브 헤더(2단 헤더의 아랫단 — 플랫폼 열 등) | 배경 `#44546A` · 글씨 `#F3F3F3` |
| 라벨 셀(환경 블록 등 입력 짝의 이름 칸) | 배경 `#EDEFF4` · 글씨 `#000000` |
| **실행 채움 셀** — 설계 시점에는 비어 있고 실행 단계에서 채워지는 칸 | 배경 `#FFF9C4` |
| 안내 주석(※ 문구) | 글씨 `#555555` |

노란색의 뜻은 **"누가 채우는가"가 아니라 "언제 채워지는가"** 입니다(2026-08-02 재정의). 이
프로젝트의 자동화는 xlsx가 아니라 tc-input json을 읽고 결과를 별도 시트로 내므로, "실행자가
손으로 입력한다"는 옛 정의는 자동화 대상 케이스에 성립하지 않습니다. 채우는 주체가 사람이든
자동화든 상관없이 **설계자는 노란 칸을 건드리지 않는다**는 규약만 남깁니다.

## 3. 상태 배색 (옵션 — §4에서 시트별로 켭니다)

연한 채움 + 진한 글씨 방식이며, 값 기반 조건부 서식으로 적용해 값을 바꾸면 색이 따라
바뀝니다.

| 값 | 채움 | 글씨 |
|---|---|---|
| Pass · Resolved | `#D1FAE5` | `#047857` |
| Fail · Open · High | `#FEE2E2` | `#B91C1C` |
| Blocked · Reopen · Medium | `#FEF3C7` | `#B45309` |
| NI · Closed · Low | `#E5E7EB` | `#4B5563` |
| In Progress | `#DBEAFE` | `#1D4ED8` |

## 4. 시트별 옵션 (tc-sheet-master 기준)

새 xlsx 산출물을 만들 때는 그 산출물의 정의 문서에 이 표 형식으로 옵션을 추가합니다.

| 시트 | 틀 고정 | 자동 필터 | 상태 배색 | 실행 채움 셀(노랑) | 데이터 글자 크기 |
|---|---|---|---|---|---|
| Test Case | 없음 | 없음 | 미적용(추후 결정) | 환경 블록 · Result · Issue No. | 9pt |
| Summary | 없음 | 없음 | 미적용 | 없음 | 기본 11pt |
| 이슈 관리 시트 | 헤더 행 고정 | 있음 | 미적용(추후 결정) | 없음(전 컬럼 입력 시트 — 드롭다운이 오입력을 막음) | 11pt |
| 목록 | 없음 | 없음 | 미적용 | 없음 | 11pt |
| 명세서 | 없음 | 없음 | — | — | 11pt |

- 명세서는 문서형 시트라 **표 테두리 규칙 대상이 아닙니다** — 격자 숨김만 적용합니다

### 4-1. 설계 시트와 결과 시트

같은 TC라도 배포되는 **설계 시트**(`test-case/…-tc-v{X.Y}.xlsx`)와 자동화가 만드는
**결과 시트**(`automation/result/…-result.xlsx`)는 옵션이 반대입니다.

| 산출물 | 실행 채움 셀(노랑) | 상태 배색 |
|---|---|---|
| 설계 시트 (배포물) | 적용 — Result·Issue No.·환경 블록 | 미적용 |
| 결과 시트 (자동 생성) | **미적용** | **적용** — Pass/Fail/Blocked/NI |

설계 시트에서 노랑은 "여기가 실행이 채울 자리"라는 안내라 필요합니다. 결과 시트는 이미
채워진 값이고 사람이 건드릴 대상이 아니므로 노랑이 오해를 만들며, 색은 결과를 읽는 데
씁니다. 결과 시트의 환경 블록은 실행 환경 정보로 자동 기입됩니다.
- **노란색은 실행 단계에서 채워지는 칸에만 씁니다.** 설계 시점에 한 번 정해지는 값은 일반
  셀로 둡니다 — 두 성격을 같은 색으로 묶으면 "실행 중에는 노란 데만 건드린다"는 규약이
  흐려집니다 (2026-08-02 확정: Summary C4의 노란 채움 해제)
- **기준 골격 버전(Summary C4)은 생성 스크립트가 자동으로 채웁니다.** 값 형식은
  `{프로젝트}-tree-v{X.Y}`이며 TC 설계 입력(tc-input json)의 골격 버전을 그대로 씁니다.
  마스터 템플릿에는 프로젝트가 없으므로 `{프로젝트}-tree-vX.Y` 플레이스홀더가 남습니다.
  사람이 옮겨 적지 않으므로 TC 세트와 골격 버전이 어긋날 수 없고, 이 형식은 골격 태그
  규칙(`qa-git-rules.md` §7)과 같아 태그·시트·파일명이 한 좌표로 읽힙니다

## 5. 드롭다운·목록 시트 규약

- 드롭다운 목록의 정본은 **'목록' 시트 한 곳**입니다. 전 시트의 데이터 검증이 이 시트의
  범위를 참조하며, 같은 목록을 쓰는 컬럼(영향/수정 버전)은 같은 범위를 참조합니다
- 목록 시트는 **숨기지 않고 맨 뒤에 배치**합니다 — 값 체계 자체가 포트폴리오 전시물입니다
- 검증은 신규 입력에만 작동합니다. 목록 항목의 명칭이 바뀌어도 기존 데이터 행의 값은
  소급 변경하지 않습니다(이력 보존)
- 기능 트리 개정 시 레이블 목록을 함께 갱신합니다(정본 수정 체크리스트 연동)
- 멀티 선택 드롭다운은 xlsx 표준 기능에 없으므로, 복수 값 컬럼(관측자)은 검증 없이
  **쉼표 구분 자유 입력**으로 두고 작성 규칙을 명세서에 기재합니다
